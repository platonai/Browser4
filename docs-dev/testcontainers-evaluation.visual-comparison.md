# Testcontainers vs Docker Compose 可视化对比

## 开发者工作流对比

### 当前方案（Docker Compose）

```
┌─────────────────────────────────────────────────────────┐
│                     开发者工作流                          │
└─────────────────────────────────────────────────────────┘

第 1 步: 启动服务
┌──────────────────┐
│ $ docker compose │
│   up mongodb     │ ← 手动操作（容易忘记）
└────────┬─────────┘
         │ 等待 5-10 秒
         ↓
┌──────────────────┐
│ MongoDB 启动      │
└────────┬─────────┘
         │
         ↓
第 2 步: 运行测试
┌──────────────────┐
│ $ mvn test       │
│   -DrunITs=true  │
└────────┬─────────┘
         │ 测试执行
         ↓
┌──────────────────┐
│ 测试完成          │
└────────┬─────────┘
         │
         ↓
第 3 步: 清理（可选）
┌──────────────────┐
│ $ docker compose │
│   down           │ ← 手动清理
└──────────────────┘

问题：
❌ 3 个手动步骤
❌ 容易忘记启动服务
❌ 状态可能污染下次测试
```

### Testcontainers 方案

```
┌─────────────────────────────────────────────────────────┐
│                     开发者工作流                          │
└─────────────────────────────────────────────────────────┘

一步完成
┌──────────────────┐
│ $ mvn test       │
│   -DrunITs=true  │ ← 唯一的命令
└────────┬─────────┘
         │
         ↓ Testcontainers 自动：
         ├─ 检查 Docker 可用性
         ├─ 拉取/启动 MongoDB 容器
         ├─ 配置连接参数
         ├─ 运行测试
         ├─ 停止容器
         └─ 清理资源
         │
         ↓
┌──────────────────┐
│ 测试完成          │
└──────────────────┘

优势：
✅ 1 个命令完成所有操作
✅ 零配置
✅ 自动清理
```

## 测试隔离性对比

### 当前方案（共享 MongoDB）

```
┌──────────────────────────────────────────────────┐
│              共享 MongoDB 实例                     │
│         localhost:27017                          │
└──────────────────────────────────────────────────┘
    ↑           ↑           ↑           ↑
    │           │           │           │
┌───┴───┐   ┌───┴───┐   ┌───┴───┐   ┌───┴───┐
│ Test1 │   │ Test2 │   │ Test3 │   │ Test4 │
└───────┘   └───────┘   └───────┘   └───────┘

问题：
❌ 测试 1 写入的数据可能影响测试 2
❌ 并行运行时可能冲突
❌ 失败后状态污染
```

### Testcontainers 方案（独立容器）

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│   MongoDB   │   │   MongoDB   │   │   MongoDB   │   │   MongoDB   │
│ :54321      │   │ :54322      │   │ :54323      │   │ :54324      │
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │                 │                 │                 │
   ┌───┴───┐         ┌───┴───┐         ┌───┴───┐         ┌───┴───┐
   │ Test1 │         │ Test2 │         │ Test3 │         │ Test4 │
   └───────┘         └───────┘         └───────┘         └───────┘

优势：
✅ 完全隔离
✅ 可并行运行
✅ 自动清理
```

## 执行时间对比

### 场景 1: 单个测试类

```
Docker Compose 方案:
├─ 手动启动服务: 5-10 秒
├─ 运行测试: 2 秒
└─ 总计: 7-12 秒

Testcontainers 方案:
├─ 自动启动容器: 5-10 秒
├─ 运行测试: 2 秒
└─ 总计: 7-12 秒

结论: 时间相近，但 Testcontainers 自动化更好
```

### 场景 2: 10 个测试类（无容器复用）

```
Docker Compose 方案:
├─ 启动服务一次: 10 秒
├─ 运行 10 个测试: 20 秒
└─ 总计: 30 秒

Testcontainers 方案（无复用）:
├─ 启动容器 10 次: 100 秒
├─ 运行 10 个测试: 20 秒
└─ 总计: 120 秒 ❌ 慢 4 倍

结论: 需要启用容器复用！
```

### 场景 3: 10 个测试类（有容器复用）

```
Docker Compose 方案:
├─ 启动服务一次: 10 秒
├─ 运行 10 个测试: 20 秒
└─ 总计: 30 秒

Testcontainers 方案（有复用）:
├─ 启动容器一次: 10 秒
├─ 运行 10 个测试: 20 秒
└─ 总计: 30 秒 ✅ 时间相同

结论: 启用 withReuse(true) 后性能相当
```

## 适用场景决策树

```
需要使用 MongoDB 进行测试？
    │
    ├─ 是 ─→ 是开发者本地测试吗？
    │        │
    │        ├─ 是 ─→ ✅ 使用 Testcontainers
    │        │        （自动管理，零配置）
    │        │
    │        └─ 否 ─→ 是 CI/CD 测试吗？
    │                 │
    │                 ├─ 是 ─→ ⚠️ 保持 Docker Compose
    │                 │        （已优化，无需迁移）
    │                 │
    │                 └─ 是 SDK 测试吗？
    │                          │
    │                          ├─ 是 ─→ ✅ 使用 Testcontainers
    │                          │        （独立环境保证）
    │                          │
    │                          └─ 否 ─→ 具体场景具体分析
    │
    └─ 否 ─→ 不需要 Testcontainers
```

## 架构集成方案

### 推荐的混合架构

```
┌─────────────────────────────────────────────────────────┐
│                   Browser4 测试体系                       │
└─────────────────────────────────────────────────────────┘

┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  单元测试     │      │  集成测试     │      │   E2E 测试    │
│              │      │              │      │              │
│ • 无外部依赖  │      │ • MongoDB    │      │ • Chrome     │
│ • < 5 秒     │      │ • Redis      │      │ • Mock 服务  │
│ • Mock/Stub  │      │ • 真实服务    │      │ • 完整链路    │
└──────────────┘      └──────────────┘      └──────────────┘
        │                     │                     │
        │                     │                     │
        ↓                     ↓                     ↓
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│ JUnit 5      │      │ JUnit 5      │      │ Selenium     │
│              │      │ +            │      │ WebDriver    │
│              │      │ Testcontainers│      │              │
└──────────────┘      └──────────────┘      └──────────────┘
                              │
                              ├─ 开发者本地 ────→ Testcontainers
                              ├─ CI/CD ─────────→ Docker Compose
                              └─ SDK 测试 ──────→ Testcontainers

关键决策：
✅ 开发者本地 = Testcontainers（自动化）
✅ CI/CD = Docker Compose（已优化）
✅ SDK 测试 = Testcontainers（独立环境）
❌ 浏览器测试 = 保持现有方案（Chrome Launcher）
```

## 总结

### 最佳实践

```
┌─────────────────────────────────────────────┐
│         Testcontainers 使用指南              │
├─────────────────────────────────────────────┤
│                                             │
│  ✅ DO（推荐）                               │
│  • 用于开发者本地集成测试                     │
│  • 用于 SDK 契约测试                         │
│  • 启用容器复用（withReuse(true)）           │
│  • 配合 JUnit 5 Tags 使用                   │
│                                             │
│  ❌ DON'T（不推荐）                          │
│  • 不要全面替换 CI/CD 中的 Docker Compose   │
│  • 不要用于浏览器自动化测试                   │
│  • 不要在快速单元测试中使用                   │
│  • 不要强制所有测试都用 Testcontainers      │
│                                             │
└─────────────────────────────────────────────┘
```
