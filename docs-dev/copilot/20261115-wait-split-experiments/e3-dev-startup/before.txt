## 3. why a *closed* loopback port costs the whole budget

.NET `TcpClient.Connect` to explicit IPv4 endpoints (`127.0.0.1`):

```
8282: connected in 2ms        (a live backend of another checkout)
8283: ConnectionRefused in 2084ms
8284: ConnectionRefused in 2023ms
18182: ConnectionRefused in 2061ms
9999: ConnectionRefused in 2057ms
```

On this host the SYN to a closed loopback port is dropped, not answered with RST,
so ECONNREFUSED only arrives after ~2 s. Any probe budget below that is spent in
full — which is exactly what the 250 ms budget did.

## 4. first attempt at a fix made it worse

Ordering the managed-process registry *first* replaced the TCP probe with
`is_process_running`, which on Windows spawned `tasklist`:

```

[startup] dev-port=1185ms
[timing] startup=1186ms http=0ms server=0ms net=0ms calls=0 total=1186ms
```

The "cheap registry check" was the expensive part.
