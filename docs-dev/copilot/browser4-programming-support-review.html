总体结论

Browser4 的编程支持定位为「浏览器自动化 Agent 的辅助编码能力」：以统一的 coding 工具域（28 个方法）为核心，提供完整的文件读写、代码搜索、Shell/构建/测试/版本控制执行与浏览器内 JS 求值，并配套一套分层命令白名单安全模型。这套能力足以支撑「写脚本、改配置、跑构建、做测试、调页面」类轻量开发任务，工程质量与安全设计优于多数同类型项目；但不具备 IDE 级深度编程能力（无 LSP/语义理解、无结构化编辑、无代码审查/重构工具），距离 Claude Code / Codex 类专用编程 Agent 还有明显差距。

综合评级：B+（良好，有明确提升空间） — 作为辅助编码能力足够实用，作为独立编程 Agent 尚不完整。

3. 编程能力详解

3.1 统一 coding 域 — 架构亮点

CodingToolExecutor 将 Shell 与文件系统组合为单一 Target（shell + fs），以 28 个方法统一暴露。相比旧架构（fs/shell 分离），FileSystemToolExecutor 与 ShellToolExecutor 已标注 @Deprecated，提示迁移到 coding.*。domain 别名（dev → coding）保证向后兼容。该设计是本次评估中最值得肯定的一点：单一入口 + 明确演进方向。

3.2 文件系统（CodingAgentFileSystem）

read(path) readLines(p,s,e) write(p,content) append(p,c) replace(p,o,n,count) mkdir(p) delete(p,rec) copy(s,d) move(s,d) listDir(p,depth) glob(pattern) grep(re,p,f) stat(p) diff(p) changeSummary() languages() workspaceRoot()

亮点

  • 快照回滚 每次写操作前自动 snapshotFile()，diff/changeSummary 可审计全部变更（含 created/modified/deleted 状态）——这是同类项目少有的能力。
  • 健壮性 5MB 读取上限、60+ 二进制扩展名识别（仅返回元数据）、glob 结果上限 10,000、grep 结果上限 500。
  • 安全 默认沙箱在 workspaceRoot 内，resolvePath 双重校验拦截路径穿越；外部访问需 allowExternalAccess=true 显式开启。

局限

  • replace 仅字符串替换 无正则替换、无行号定位编辑（readLines 与 replace 之间缺「按行区间替换」）。
  • diff 为朴素逐行比较 非标准 Myers diff，大文件/复杂编辑场景输出噪声大。
  • grep 无并发/索引 每次全树遍历，大仓性能有限。

3.3 Shell 执行与安全模型（CodingAgentShell）

命令校验采用优先级分层的白名单策略，是本模块安全设计的核心：

优先级策略说明
1硬编码黑名单模式rm -rf /、mkfs.*、dd of=/dev/、fork 炸弹、shutdown 等 10 条正则，不可被任何配置覆盖
2显式 deny / denyPattern绝对否决，优先于一切放行规则（含 SAFE 集）
3显式 allow / allowPattern绕过分类检查，用于扩展非标准工具（如 ffmpeg）
4分类检查SAFE（只读，恒放行）→ DEV（90+ 工具，默认放行）→ NETWORK（需 opt-in）→ DESTRUCTIVE（需 opt-in）
5PATH 回退未分类但存在于 PATH 的命令在 allowDevTools=true 时放行
  • 可解释 explain(command) 返回每条命令被放行/拦截的具体原因，便于审计与调试。
  • 会话化 结果按 sessionId 留存，shellOutput/shellStatus/shellList 支持异步取回；持久环境变量 shellSetEnv。
  • 防护 超时 120s（上限 600s）、输出截断 200KB、超时强杀进程、Windows/Linux 双平台适配。
  • 注意 默认 allowDestructive=true——删除类命令（rm/del/kill 等）在默认配置下即被放行（仅受黑名单模式限制），独立部署时建议收紧。

3.4 浏览器内编程（tab 域）

  • tab.eval(expression) / tab.evaluateValue(expression, selector)：页面级与元素级 JS 求值，支持将表达式作为 functionDeclaration 转发，可用于 DOM 操作、数据提取、页面调试。
  • tab.consoleMessages(level) / tab.consoleClear()：首次调用即注入控制台拦截器并缓冲消息，支持按级别过滤——对前端调试类编程任务实用。
  • tab.saveStorageState / loadStorageState：cookies + localStorage 序列化/恢复，支撑登录态复用的测试场景。

5. 优势总结

  1. 统一工具域设计：coding 域整合 Shell+FS，架构演进方向清晰，旧域明确废弃。
  2. 安全模型成熟：分层白名单 + 硬编码黑名单 + 可解释策略 + 路径穿越防护，是同类项目中少见的完整度。
  3. 变更可审计：写操作快照 + diff + changeSummary，为 Agent 自主改代码提供了回退与审查基础。
  4. 工程化细节：超时强杀、输出截断、二进制防护、跨平台、会话化结果管理。
  5. 防递归与防失控：CLI 嵌套 agent 拦截、命令超时上限等设计体现了对自主 Agent 风险的清醒认知。
  6. 扩展路径清晰：自定义 domain/target/executor 三级扩展 + 动态 prompt 注入。

6. 短板与风险

短板影响严重度
无 LSP / 语义级代码理解无法利用编译器诊断、符号/引用/类型查询；改代码全靠文本匹配，大型重构易出错中
无结构化代码编辑replace 仅字符串级，无正则/行区间/多文件批量编辑，长任务 token 开销大中
无独立代码执行运行时需借助 shell 间接执行脚本，无 sandbox 化的 run-code/REPL 抽象低-中
无代码审查/修复回路Agent 无法「编译→看错误→修」的自闭环；依赖 LLM 自觉调用 shell中
默认 allowDestructive=true删除类命令默认放行，独立部署/多租户场景有风险敞口中
编程技能空白skills/ 下仅有浏览器自动化类技能（browser4-cli 等），无内置 coding skill（如「修 bug」「写测试」工作流）低
grep/glob 无索引大仓库下搜索延迟，Agent 等待成本高低

7. 改进建议

P1 · 高价值 引入代码智能层（LSP 或轻量索引）

在 coding 域新增 diagnostics(path)（编译诊断）、symbols(pattern)（符号查找）、references(symbol)（引用查询）方法，可直接对接 JDTLS / rust-analyzer / typescript-language-server 等 LSP。这是从「文本编辑」跃迁到「编程 Agent」最关键的一步。

P1 · 高价值 补齐编辑原语

新增 replaceRegex、editLines(path, start, end, content)、insertAfter(path, anchor, content)；diff 升级为标准算法（如 Myers/Patience），并在 replace 后自动输出 diff 供 Agent 自检。

P1 · 高价值 内置「编译-测试-修复」回路技能

创建 coding skill（如 fix-bug：读错误→定位→修改→重跑测试→验证），把零散工具组合为可复用工作流；同时收紧独立部署默认值（allowDestructive=false）。

P2 · 增强 沙箱化代码执行

新增 runCode(language, code) 抽象（Node/Python 子进程 + 资源限制 + 独立临时目录），避免 Agent 手动拼 shell 命令，也便于统一超时/内存控制。

P2 · 增强 搜索性能

为 grep/glob 增加缓存索引或排除目录配置（node_modules/target/.git 等），大仓库下显著降低 Agent 等待时间。

8. 结论

Browser4 的编程支持在「Web Agent 的辅助编码」这个定位上是称职且超出预期的：统一工具域、完整的安全模型、可审计的变更追踪，工程质量扎实。它能让 Agent 可靠地完成读写代码、跑构建测试、调页面调试等任务，与浏览器自动化能力形成互补闭环。

但其能力边界在「代码理解」这一层——没有 LSP/语义索引、没有结构化编辑、没有内置的修 bug/写测试工作流，因此现阶段更适合作为自动化 Agent 的附属能力，而非独立的编程 Agent。若按 P1 建议补齐代码智能层与编辑原语，编程支持评级可从 B+ 提升至 A-，具备与主流编程 Agent 竞争的基础。
