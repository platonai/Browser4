# Issues Found - Amazon Whiteboard Pens Comparison Task

## Summary

Issues found while using browser4-cli to search Amazon for whiteboard pens, compare the first 4 results, and write a comparison file.

---

## Issue 1: `open <url>` command fails on first attempt

**Severity:** High
**Category:** Correctness

The command `browser4-cli open https://www.amazon.com/` failed with:
```
Error: ERROR: browser_navigate failed: Cannot find context with specified id
```
The workaround was to run `browser4-cli open` (no URL), then `browser4-cli goto <url>` separately. The `open` command with a URL argument should work according to the SKILL.md documentation (`open https://example.com/`), but it fails in practice.

---

## Issue 2: Amazon bot detection blocks form-based search

**Severity:** High
**Category:** Correctness / Functionality

Both methods of submitting the search form (clicking the "Go" button with `click e594` and pressing `Enter` with `press Enter`) resulted in Amazon's error page:
- Page title: "Sorry! Something went wrong!"
- Content: 503-style error page with "Dogs of Amazon" link

This is likely Amazon's anti-bot protection detecting the automated browser. The workaround was to navigate directly to the search URL: `goto "https://www.amazon.com/s?k=pens+to+draw+on+whiteboards"`. This suggests the form submission triggers additional bot-detection heuristics that direct URL navigation bypasses.

---

## Issue 3: Server becomes unresponsive after multiple operations

**Severity:** Medium
**Category:** Reliability

After several page navigations and interactions, the browser4-cli HTTP server became unresponsive:
```
Error: HTTP request failed: error sending request for url (http://localhost:8182/mcp/call-tool)
```
The next command (`goto`) worked fine, suggesting this is an intermittent connectivity issue. Could indicate a race condition or resource leak in the server.

---

## Issue 4: Sponsored results interleaved with organic results causes ambiguity

**Severity:** Medium
**Category:** Correctness

Between the 3rd and 4th organic search results, Amazon inserted a sponsored ad for the same product (Shuttle Art) that appears as the 4th organic result. This means:
- If counting by DOM position, "first 4" would include a duplicate
- The Shuttle Art product appears twice in the results page
- The task asked to compare "the first 4 ones" but it's ambiguous whether this means organic-only or all results

---

## Issue 5: Product #3 is not a "pen" but liquid chalk markers

**Severity:** Low
**Category:** Search Relevance

The search for "pens to draw on whiteboards" returned Liquid Chalk Markers as the 3rd result. These are fundamentally different from dry-erase markers/pens:
- They use wet-erase ink, not dry-erase
- They require water to clean, not a dry eraser
- They can leave permanent marks on porous surfaces
- They are technically "chalk markers", not "pens"

This is an Amazon search relevance issue, but worth noting for task accuracy.

---

## Issue 6: International shipping context skews results

**Severity:** Medium
**Category:** Correctness

Amazon is showing results with delivery to Japan (not the US). Every page displays this alert:
> "We're showing you items that ship to Japan. To see items that ship to a different country, change your delivery address."

All prices show international shipping costs ($7.42-$8.42 delivery) and delivery dates (~11 days out). This may affect which products are shown and at what prices, making the comparison less useful for US-based shoppers.

---

## Issue 7: Snapshot files are excessively large

**Severity:** Low
**Category:** Efficiency

The snapshot YAML files generated by the tool can be extremely large. The Amazon search results page snapshot exceeded 27,000 tokens, making it impossible to read in a single operation with a 25,000 token limit. This forces partial reads and makes it harder to find specific elements.

---

## Issue 8: No command chaining or scripting support in non-batch mode

**Severity:** Medium
**Category:** Efficiency

Each browser interaction requires a separate `cargo run -- <command>` invocation. This means:
- Cargo re-checks dependencies on each invocation (adds ~0.12s overhead per command)
- Each command prints the full "Finished" compilation line
- Session state must be maintained across separate process invocations
- No way to chain commands like `fill e130 "query" && press Enter`
- The overall workflow requires 15+ separate shell commands for a simple task

---

## Issue 9: Element refs become stale after navigation

**Severity:** Medium
**Category:** Correctness

Element refs (e.g., `e130` for the search box) from a snapshot on one page become invalid after navigating to a different page. The ref `e130` on the Amazon homepage referred to the search box, but after navigating to a search results page, `e130` may point to a completely different element or not exist. This requires taking a fresh snapshot and finding new refs after each navigation.

---

## Issue 10: Eval command has difficult quote escaping

**Severity:** Low
**Category:** Usability

The `eval` command requires careful quote escaping. Single quotes within the JavaScript expression must be escaped for the shell, and the JavaScript selector syntax (`'#feature-bullets'`) conflicts with shell quoting. The working command looked like:
```
cargo run -- eval "document.querySelector('#feature-bullets')?.innerText || 'no feature bullets found'"
```
This is error-prone and difficult to compose correctly.

---

## Issue 11: No built-in data extraction for common patterns

**Severity:** Medium
**Category:** Efficiency

To extract structured product data (price, rating, features), manual `eval` calls with custom JavaScript selectors were required. The tool could benefit from built-in extraction capabilities or templates for common e-commerce patterns. This would reduce the number of commands needed and improve extraction reliability.

---

## Issue 12: Cargo working directory resets to `bin/tests`

**Severity:** Low
**Category:** Usability

After every `cargo run` command, the shell outputs:
```
Shell cwd was reset to D:\workspace\Browser4Team\submodules\Browser4\sdks\browser4-cli\bin\tests
```
This suggests the tool changes the working directory during execution and resets it afterward. While not blocking, it indicates the tool does not preserve the user's working directory context between commands.

---

## Issue 13: No `go-back` reliability guarantee

**Severity:** Low
**Category:** Correctness

After receiving the Amazon 503 error from the search form submission, `go-back` successfully returned to the homepage. However, on single-page applications or pages that modify browser history, `go-back` may not reliably return to the expected state. The tool provides no way to verify or enforce page state after navigation.
