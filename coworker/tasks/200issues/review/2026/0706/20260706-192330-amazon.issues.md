### Issue 1: Auto-discover (htmlsnapshot inspect) defaults to generic selectors, not product cards

**Severity:** Medium
**Category:** UX

#### Reproduction

```
cargo run -- htmlsnapshot inspect
```
On an Amazon search results page.

#### Expected Behavior

The auto-discovery should identify `.s-result-item[data-component-type='s-search-result']` as the primary repeating pattern and suggest product-specific selectors (titles, prices, ratings).

#### Actual Behavior

The auto-discovery analyzed `div#a-page` and navigation elements, suggesting generic selectors like `div` and `span`. A separate targeted `inspect` call with the specific container selector was needed to discover product-level selectors.

#### Root Cause Analysis

The auto-discovery algorithm picks the first repeating element from `:root`. On Amazon, the navigation keyboard shortcuts divs and page-level containers are found first. The algorithm doesn't prioritize elements that look like "product cards" (consistent geometry, image+text+price children).

#### Code Pointer

`Likely in the `htmlsnapshot inspect` implementation — the container-priority heuristic.`

#### AI Suggested Improvement

- Prioritize containers with consistent child structure (image + heading + price pattern) over navigation elements
- When multiple repeating patterns exist, surface all of them with labels (e.g., "Navigation items", "Product cards", "Footer links")
- Add a `--category` or `--pattern` flag to hint at the type of repeating element being sought

### Issue 2: Documentation's recommended CSS selectors fail on non-English Amazon locale

**Severity:** Medium
**Category:** Documentation

#### Reproduction

1. Navigate to amazon.com (which auto-detects locale and may serve Chinese UI to Singapore visitors)
2. Follow scenario 15b from `htmlsnapshot-scenarios-amazon.md`
3. Run `htmlsnapshot get all text "h2 a.a-link-normal"`

#### Expected Behavior

Product titles should be returned.

#### Actual Behavior

The selector `h2 a.a-link-normal` returns an empty array `[]`. The working selector on this locale is `a.a-link-normal.s-line-clamp-4`.

#### Root Cause Analysis

Amazon serves different HTML structures depending on the detected locale. The page was served in Chinese (简体中文) for a Singapore-based browser. The `h2` wrapper around product title links is absent in this locale variant, replaced by a flat `a` tag with `s-line-clamp-4` class.

#### Code Pointer

``skills/browser4-cli/references/htmlsnapshot-scenarios-amazon.md` — scenario 15b selector recommendations.`

#### AI Suggested Improvement

- Add a warning in scenario 15b that CSS selectors vary by Amazon locale, and show fallback selectors for common locale variants
- Include `a.a-link-normal.s-line-clamp-4` as an alternative title selector in the documentation
- Suggest using `htmlsnapshot inspect ".s-result-item[data-component-type='s-search-result']"` as the first step to discover locale-specific selectors, rather than assuming the documented selectors will work

#### Actual Behavior

The `@file` path appears to resolve relative to the current working directory (which is `cli/browser4-cli`), requiring `../../` prefix to reference files in the repo root.

### Issue 7: `snapshot -v 0` truncation loses product data — products only appear in later viewports

**Severity:** Medium
**Category:** Discoverability

#### Reproduction

1. Search Amazon for a product
2. Run `snapshot -v 0` to view the top of the page

#### Expected Behavior

Product results should be visible in the accessibility tree for viewport 0, which is the natural place a user would look for search results.

#### Actual Behavior

The snapshot showed 6 viewports total (the page is ~5530px tall with a 986px viewport). Viewport 0 showed only the page header, navigation, and hero banner. The product results start further down the page. A new user might think the search failed or the page is empty.

#### Root Cause Analysis

Amazon's page has a large header area (navigation, search bar, filters) that consumes the first viewport. The `-v 0` default captures only what's visible at the top.

#### AI Suggested Improvement

- When `snapshot` detects a search results page (URL contains `/s?k=`), automatically capture enough viewports to include the first few results, or suggest `-v 1` in the output
- Add a `--results` or `--content` flag that auto-calculates which viewports contain the main content area
- The viewport hint in the snapshot footer is good ("6 viewports... snapshot -v 1") — consider making it more prominent
