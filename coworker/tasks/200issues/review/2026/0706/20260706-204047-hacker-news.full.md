### Issue 1: Click action times out with no navigation and misleading error guidance

**Severity:** High

**Category:** Reliability

**Reproduction:**
```bash
cd cli/browser4-cli && cargo run -- goto "https://news.ycombinator.com/news"
cargo run -- snapshot -v 0
cargo run -- click e552   # click on story #2 link
```

**Expected:** Click navigates to the linked page and returns a snapshot of the new page.

**Actual:** HTTP request timed out after 120 seconds. The error message suggests "Click/press actions may trigger page navigation that succeeds despite the timeout. Check the current page with `snapshot` to verify" — but in this case, no navigation occurred at all. The browser remained on the HN front page.

**Root Cause:** The HTTP client timeout (120s) fires before the page navigation completes. The reprog.wordpress.com site may be slow to respond, causing the CDP `click` + wait-for-navigation cycle to exceed the timeout. The error message's assumption that navigation might have succeeded anyway is incorrect for this case.

**Code Pointer:** `cli/browser4-cli/src/http.rs` — HTTP client timeout configuration; `cli/browser4-cli/src/commands.rs` — click command timeout/error handling.

**AI Suggested Improvement:**
- Increase the HTTP client timeout for navigation-triggering actions (click on links, press Enter on forms) beyond 120s, or make it configurable via a `--timeout` flag
- After a click timeout, automatically check whether navigation actually occurred and report the result rather than showing a generic "might have worked" message
- Consider decoupling the click action from the navigation wait: fire the click, then separately wait for navigation with its own timeout
- The error message should say "Navigation did NOT occur" or "Navigation MAY have occurred" based on actually checking the page URL, not a generic guess

### Most Confusing Aspects
1. **Understanding the snapshot workflow.** The YAML file goes to disk, but refs are needed for interaction. The disconnect between "output shows a file path" and "now I need to read that file to find refs" is jarring for a first-time user.
2. **When to use snapshot vs htmlsnapshot.** For content reading, `htmlsnapshot get text` is far better, but the core loop only mentions accessibility tree snapshots. The decision tree helps but requires reading the full SKILL.md.
3. **Viewport management.** The concept of viewports is powerful but adds cognitive load — pages have N viewports, `-v 0` only shows the top, and you need to paginate through them. For long articles, it's unclear when you've "seen everything."

### Most Valuable Improvements
1. **Show refs in goto output** — eliminate the mandatory extra `snapshot` step for simple navigation+click workflows.
2. **Configurable timeouts** — the 120s hardcoded timeout caused the only functional failure.
3. **Better default output for snapshot** — show a preview inline, not just a file path. This alone would dramatically improve the interactive CLI experience.
4. **Add a content-reading pattern to the core loop** in SKILL.md — `htmlsnapshot` → `htmlsnapshot get all text` should be a first-class workflow.

### Overall Usability Rating: **6.5 / 10**

**Strengths:**
- The accessibility tree ref system is elegant and works well for interaction (when it works)
- `snapshot grep` is a powerful discovery tool
- `htmlsnapshot get all text` with CSS selectors is efficient for extraction
- `wait --load networkidle` handled the Cloudflare challenge gracefully
- Command-specific `--help` is comprehensive with good examples
- The SKILL.md methodology is well-structured with decision trees and patterns

**Weaknesses:**
- The multi-step workflow (goto → snapshot → read file → find ref → interact) is verbose for simple tasks
- File-based snapshot output breaks the interactive CLI flow
- Hardcoded timeouts can silently fail with misleading error messages
- Two parallel extraction systems (accessibility tree snapshots vs htmlsnapshot) create confusion about which to use when
- The `cargo run --` invocation from source is noisy and verbose on Windows
- Ref lifecycle management requires manual re-snapshotting and re-discovery
