### Issue 1: Click on off-screen elements fails silently with misleading message

**Severity:** High
**Category:** UX

#### Reproduction

`cargo run -- goto "https://www.amazon.com/s?k=Calabi-Yau"` then `cargo run -- click "a.s-pagination-item.s-pagination-next" --follow`

#### Expected Behavior

Element should be scrolled into view and clicked, or a clear error should say "element is off-screen, scroll first."

#### Actual Behavior

Click reports success with `✓ Clicked` but then warns `⚠️ Click ... did not result in navigation — page URL is unchanged. The element may be off-screen`. The suggestion mentions `--follow` but `--follow` was already used. The real cause (off-screen element) is buried as a secondary guess.

#### Root Cause Analysis

The CLI doesn't auto-scroll elements into view before clicking. The error message conflates two possible causes (no-navigation vs off-screen) and suggests `--follow` as a fix when `--follow` is already in use.

#### Code Pointer

``cli/browser4-cli/src/main.rs` — click handling and error reporting`

#### AI Suggested Improvement

- Auto-scroll elements into view before clicking, or at minimum return a clear error: "Element is off-screen at [coordinates]. Use `scroll` to bring it into view first."
- Don't suggest `--follow` when the user already passed it
- Consider adding a `--scroll-into-view` flag to click/hover/dblclick

### Issue 2: `htmlsnapshot inspect` auto-discover fails on e-commerce product grids

**Category:** Reliability

#### Reproduction

`cargo run -- goto "https://www.amazon.com/s?k=Calabi-Yau"` then `cargo run -- htmlsnapshot` then `cargo run -- htmlsnapshot inspect`

#### Expected Behavior

Auto-discover should identify product card selectors (like `div[data-component-type="s-search-result"]` or `div.s-result-item`).

#### Actual Behavior

The tool analyzed 20 of 1130 `div` elements, but the sample (from top-of-page nav elements, not product cards) produced irrelevant suggestions like `span.shortcut-key`. No product-card selectors were suggested.

#### Root Cause Analysis

The auto-discovery samples the first 20 matches, which in a typical web page are header/nav elements, not the main content. It should prioritize elements in `<main>` or use a smarter sampling strategy (stratified by DOM depth/position).

#### Code Pointer

``browser4-rest/.../HtmlSnapshotController.kt` or the inspect logic`

- Sample from deeper in the DOM tree, prioritizing elements inside `<main>` or with higher y-coordinate bounding boxes
- Consider analyzing sibling-group patterns (multiple similar divs at the same DOM level)
- The SKILL.md already warns about this for generic divs, but the tool itself should be smarter

### Issue 3: Amazon geo-redirects silently change domain without warning

**Severity:** Medium
**Category:** Reliability

#### Reproduction

`cargo run -- goto "https://www.amazon.com/s?k=Calabi-Yau&page=2"`

#### Expected Behavior

Stay on amazon.com for page 2.

#### Actual Behavior

Redirected to `amazon.sg` (Singapore) with a completely different product catalog. The CLI reported the new URL in the output header but did not warn that the domain had changed.

#### Root Cause Analysis

Amazon uses geo-IP detection and redirects to local domains. The CLI follows HTTP redirects transparently without alerting the user that the domain (and thus the product catalog) has changed.

#### Code Pointer

``cli/browser4-cli/src/http.rs` or `browser4-core` page loading logic`

#### AI Suggested Improvement

- Detect when the final URL domain differs from the requested URL domain
- Emit a warning: "⚠️ Redirected from amazon.com to amazon.sg — product availability may differ"
- Consider adding a `--no-redirect` or `--stay-on-domain` option for geo-sensitive sites
- Add a `--country <code>` option to set preferred Amazon marketplace

### Issue 9: `snapshot grep` produces noisy output with full YAML paths

**Severity:** Low
**Category:** UX

#### Reproduction

`cargo run -- snapshot grep -i "下一页\|next\|pagination"`

#### Expected Behavior

Clean grep-style output showing matching lines.

Long lines with full YAML node content including inline JavaScript (`P.declare('s\\-optimized\\-pagination\\-config'...)`) make output hard to scan. Found the pagination element but had to parse through ~20 lines of noisy output.
