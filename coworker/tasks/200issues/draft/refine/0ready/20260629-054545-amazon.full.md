## C. Issues Found

### Issue 1: Invocation path is ambiguous for new users

**Severity:** Medium
**Category:** Documentation / Discoverability

**Reproduction Steps:**
1. Clone the Browser4 repo
2. Try to run `cd cli/browser4-cli && cargo run --` from an arbitrary shell location
3. The path `cli/browser4-cli` is relative and fails if not in the project root

**Expected Behavior:** Clear documentation of where to run commands from, or a single entry-point script.

**Actual Behavior:** The task instructions said `cd cli/browser4-cli && cargo run --` but this only works from the project root (`D:/workspace/Browser4/Browser4-4.11`). The `cli/` directory is inside the project root, not a top-level directory. Additionally, the npm project (`cli/`) wraps the Rust binary (`cli/browser4-cli/`), creating two layers of `browser4-cli` — a source of confusion.

**Suggested Improvement:** Add a `ROOT.md` note or update SKILL.md to clarify the project layout. Consider providing a Makefile or script that abstracts the build-and-run step.

### Issue 2: Snapshot content is not shown inline — requires extra steps to view

**Severity:** Medium
**Category:** UX / Discoverability

**Reproduction Steps:**
1. Run `snapshot -i -l 50`
2. Observe that only a file path is shown, not the snapshot content

**Expected Behavior:** A new user expects to see the snapshot content in the terminal, at least in a summarized form.

**Actual Behavior:** Only a file path to the YAML snapshot is printed. The user must run `snapshot grep` or read the file separately, adding friction to the workflow. While the docs defend this (large snapshots), first-time users find it confusing.

**Suggested Improvement:** Print a short summary (first 10-15 lines) inline alongside the file path. Or print a reminder like "Use `snapshot grep <pattern>` to search this snapshot."

### Issue 3: Price extraction requires non-obvious CSS pseudo-class filtering

**Severity:** Medium
**Category:** UX / Product

**Reproduction Steps:**
1. Search for products on Amazon
2. Run `domsnapshot get all text "span.a-offscreen"` to get prices
3. Observe that both main prices ($6.99) and per-unit prices ($0.58) are interleaved

**Expected Behavior:** A straightforward way to get only the main product prices.

**Actual Behavior:** Required using `span.a-price:not(.a-text-price) span.a-offscreen` — a workaround requiring Amazon DOM knowledge and CSS `:not()` pseudo-class familiarity. The `domsnapshot inspect` command helped discover this but still required multiple iterations.

**Suggested Improvement:** Consider adding a `--unique` or `--first-of-group` flag to deduplicate results, or adding a `--container=<selector>` flag to scope extraction to parent containers.

### Issue 5: `snapshot` and `domsnapshot` naming is confusing

**Severity:** Low
**Category:** UX / Discoverability

**Reproduction Steps:**
1. Run `help` and see `snapshot` under Core and `domsnapshot` under Snapshot
2. Try to understand the relationship

**Expected Behavior:** Clear distinction or unification of the two snapshot concepts.

**Actual Behavior:** Two similar-sounding commands (`snapshot` for accessibility tree with refs, `domsnapshot` for CSS-selector DOM queries) with different subcommand structures. `snapshot grep` searches YAML; `domsnapshot grep` searches HTML. A new user may confuse them or not know which to use.

**Suggested Improvement:** Consider renaming to `a11y-snapshot` and `dom-snapshot`, or adding a clear comparison table at the top of the snapshot section. The SKILL.md does distinguish them, but the `help` output doesn't.
