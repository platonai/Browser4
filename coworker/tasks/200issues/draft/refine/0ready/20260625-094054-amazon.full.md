## C. Issues Found

### Issue 1: `press Enter` on a ref does not trigger form submission

- **Severity:** High
- **Category:** Product / Reliability
- **Reproduction:** `fill` a searchbox, then `press Enter <same-ref>`. The page does not navigate.
- **Expected:** Pressing Enter on a focused searchbox inside a form should submit the form and navigate to search results.
- **Actual:** The URL remains unchanged. The Go button must be clicked separately.
- **Suggested Improvement:** `press Enter` on an element inside a `<form>` should trigger form submission, or the documentation should explicitly warn that `press Enter` does not submit forms.

### Issue 2: `extract` command times out (30s HTTP timeout)

- **Severity:** Critical
- **Category:** Reliability
- **Reproduction:** Run `browser4-cli extract "<instruction>"` on a large page like Amazon search results.
- **Expected:** The extract command completes and returns structured data.
- **Actual:** HTTP request timed out after 30s — `Error: HTTP request timed out [tool=agent_extract, endpoint=http://localhost:8182/mcp/call-tool, timeout=30s]`
- **Suggested Improvement:** Increase the default timeout for the extract endpoint, or provide a `--timeout` flag. The `extract` command is advertised as an AI-oriented feature but fails on real-world pages.

### Issue 3: Snapshot output does not display inline

- **Severity:** Medium
- **Category:** UX / Discoverability
- **Reproduction:** Run `browser4-cli snapshot -i -c`. Only a file path is printed.
- **Expected:** The compact snapshot tree should be displayed inline in the terminal (at minimum the first N lines).
- **Actual:** Only the file path is shown. Users must read the YAML file separately to find element refs.
- **Suggested Improvement:** Print the interactive snapshot tree directly to stdout when using `-i -c` flags, or add a `--stdout` flag. Having to open a separate file for every interaction slows workflows considerably.

### Issue 4: Silent failures in `eval` — no output, no error

- **Severity:** High
- **Category:** Reliability / UX
- **Reproduction:** Run certain `eval` commands with multi-statement JavaScript (e.g., `var` declarations + `for` loops). Some produce no output at all.
- **Expected:** Either the eval result is returned, or a clear error message is printed.
- **Actual:** Several eval commands returned nothing — not even an error code. This made debugging extremely difficult.
- **Suggested Improvement:** Always print JS evaluation results (even `undefined`), and surface JavaScript errors to the user. A `--debug` flag for eval would help.

### Issue 5: Snapshot files are excessively large for practical use

- **Severity:** Medium
- **Category:** UX
- **Reproduction:** Capture a snapshot on an e-commerce search results page.
- **Expected:** A manageable snapshot showing key interactive elements.
- **Actual:** 1,349 lines for a single search results page. Even with `-i -c` (interactive + compact), the output is still very large.
- **Suggested Improvement:** Add a `--max-lines` flag or section-based filtering. Allow filtering by heading/section (e.g., show only elements under "Search Results").

### Issue 6: No built-in e-commerce product extraction workflow

- **Severity:** Medium
- **Category:** Discoverability / Documentation
- **Reproduction:** Attempt to extract product listings from an e-commerce search results page.
- **Expected:** A documented workflow or built-in command for extracting product cards (titles, prices, ratings).
- **Actual:** Users must write raw JavaScript `eval` with page-specific CSS selectors. The `extract` command exists but timed out.
- **Suggested Improvement:** Document a reusable pattern for e-commerce extraction. Add examples to SKILL.md showing how to extract product data from Amazon, eBay, etc. Consider a `product-extract` command.

### Issue 7: `type` and `fill` behavior for search workflows is under-documented

- **Severity:** Low
- **Category:** Documentation
- **Reproduction:** A new user wants to search on a website. SKILL.md shows `fill` and `press` but doesn't explain that `fill` + `press Enter` may not submit forms on all sites.
- **Expected:** A documented pattern for search: fill → press Enter (or click the search button).
- **Actual:** The workflow requires trial and error (Enter didn't work, clicking Go did).
- **Suggested Improvement:** Add a "Common Workflows" section to SKILL.md with patterns like "Search a website: `fill <searchbox-ref> <query>` then `click <submit-button-ref>`."

### Issue 8: `fill` command format inconsistency in docs

- **Severity:** Low
- **Category:** Documentation
- **Reproduction:** Compare SKILL.md `fill <ref> "<value>"` (with quotes) vs `--help` output `fill <ref> <text>` (without quotes).
- **Expected:** Consistent formatting of arguments across all documentation.
- **Actual:** SKILL.md uses `<ref> "<value>"` with quotes around value; --help uses `<ref> <text>` without quotes.
- **Suggested Improvement:** Standardize argument formatting. Actually, in practice neither needs quotes for simple text (quotes are only needed for shell escaping), so remove quotes from SKILL.md for consistency.

### Issue 9: `open` and `goto` overlap creates confusion

- **Severity:** Low
- **Category:** UX / Discoverability
- **Reproduction:** A new user reads the help and sees both `open [url]` and `goto <url>`. Which to use?
- **Expected:** Clear guidance on when to use each.
- **Actual:** SKILL.md says "Prefer goto over manual session management," which helps, but the help output doesn't reflect this guidance.
- **Suggested Improvement:** Add a note in `--help` output: "Tip: for everyday navigation, use `goto` — it auto-manages sessions."

browser4-cli has a solid conceptual foundation — accessibility-tree snapshots with ref-based targeting is a good approach for AI agents.
