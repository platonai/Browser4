3. **`extract` as primary tool** — AI-powered extraction was the most effective approach, producing structured JSON with reviews, features, and ratings
4. **Chained commands** — `goto && snapshot` in a single shell invocation worked around session-loss issues

## C. Issues Found

### Issue 1: Session state is lost between CLI invocations

- **Severity:** High
- **Category:** Reliability
- **Reproduction:** 
  1. `browser4-cli open --headed` → session created
  2. `browser4-cli goto "https://amazon.com"` → works
  3. `browser4-cli snapshot` → fails with "Session required"
  4. `browser4-cli list` → shows "Active"
  5. Run `goto && snapshot` chained → works
  6. Next standalone call → may fail again
- **Expected:** Session persists across CLI process invocations since the server is running
- **Actual:** Session state is intermittently lost between process invocations despite `browser4-cli list` showing "Active"
- **Suggested:** Investigate session identification mechanism — possible race condition or session cookie/env var not being properly carried between processes. This was the single biggest friction point in the task.

---

### Issue 2: `-l`/`--limit` flag documented but not implemented

- **Severity:** Medium
- **Category:** Documentation
- **Reproduction:** `browser4-cli snapshot -l 200` → "too many arguments: expected 0, received 2"
- **Expected:** Limit snapshot output to N nodes as documented
- **Actual:** Flag doesn't exist; CLI help output confirms it's absent
- **Suggested:** Either implement `--limit` or remove from SKILL.md. If removed, note the gap and guide users to `-d` (depth) as alternative.

---

### Issue 3: Misleading error message for unrecognized snapshot flags

- **Severity:** Medium
- **Category:** UX
- **Reproduction:** `browser4-cli snapshot -i -l 50` → "too many arguments: expected 0, received 2"
- **Expected:** "unknown flag: -l" or similar clear error
- **Actual:** Error counts positional arguments, making it look like snapshot doesn't accept flags at all
- **Suggested:** Improve argument parsing to distinguish unrecognized flags from excess positional arguments

---

### Issue 4: `extract` command silently returns metadata-only on complex prompts

- **Severity:** High
- **Category:** Reliability
- **Reproduction:** 
  1. `browser4-cli extract "get the first 4 search results with title, price..."` → works with full `content` and `links` fields
  2. `browser4-cli extract "For each of the first 4 search results, extract: title, price, star rating..."` → returns only `{metadata: {...}}` with no `content`
- **Expected:** Second call returns content with the more detailed extraction
- **Actual:** Response file contains `success: true` but no content field — **silent partial failure**
- **Suggested:** Add validation that `content` field is present; surface warning if agent returned no data; investigate why the second prompt produced no extraction

---

### Issue 5: `domsnapshot get` returns only first match, not all

- **Severity:** Medium
- **Category:** UX / Documentation
- **Reproduction:** `browser4-cli domsnapshot get text "[data-component-type=s-search-result] h2 span"` → returns only the first product title
- **Expected:** Either return all matches (like `querySelectorAll`), or document clearly that only the first match is returned
- **Actual:** Only first match returned; no warning that other results were discarded
- **Suggested:** Add `--all` flag to return all matches as JSON array, or clarify behavior in CLI help and documentation. Without this, users needing multiple results must use `eval` or `extract`.

---

### Issue 6: Extract output requires manual file reading

- **Severity:** Low
- **Category:** UX
- **Reproduction:** Run `browser4-cli extract "..."` → output shows a file path but not the extracted data inline
- **Expected:** Option to see extracted data inline (or at least a JSON summary)
- **Actual:** Must note the timestamped file path and separately `cat`/read it
- **Suggested:** Add `--inline` flag to pipe extracted content to stdout, or display a brief summary inline

---

### Issue 7: Amazon page structure exceeds practical snapshot depth limits

- **Severity:** Low
- **Category:** Discoverability
- **Reproduction:** `browser4-cli snapshot -i -d 8` on Amazon search results doesn't show individual product cards
- **Expected:** Product listing elements visible at reasonable depth
- **Actual:** Product cards require depth >8 (Amazon's DOM is deeply nested), making interactive snapshots impractical for content-heavy e-commerce pages
- **Suggested:** Document guidance specifically for e-commerce pages; promote `extract` as the primary tool for search result pages

---

### Issue 8: No inline display of extracted content from `extract` command

- **Severity:** Low
- **Category:** UX
- **Reproduction:** Run `browser4-cli extract "..."` — CLI prints file path but not the data
- **Expected:** Extracted data shown inline or accessible via a quick command
- **Actual:** Must read the file separately
- **Suggested:** Add a `--print` flag or print a JSON preview inline

## D. Overall Assessment

### Task Completion Status
✅ **Completed** with workarounds. All four products were compared and the markdown file was written successfully.

### Estimated Task Success Rate
**~60%** for a first-time user without workarounds. Session persistence issues alone would block or frustrate most users trying basic interactive workflows. The `extract` command, when it works, is the saving grace.

### Issues Found: 8
- 2 High severity (session flakiness, extract silent failure)
- 4 Medium severity (missing flag, misleading error, domsnapshot single-match, search form impracticality)
- 2 Low severity (UX improvements)

### Major Blockers
1. **Session persistence flakiness** — makes step-by-step interactive usage unreliable
2. **Extract silent partial failure** — returns success without data on complex prompts

### Most Confusing Aspects
1. Why does `snapshot` fail with "Session required" when `list` shows "Active"?
2. Why does `domsnapshot get` only return one result?
3. Why does `extract` sometimes return content and sometimes not?
4. Where is the `-l` flag documented in SKILL.md?

### Most Valuable Improvements
1. **Fix session persistence** — this is critical for interactive usage
2. **Add `--all` to domsnapshot get** — or document the single-match limitation
3. **Add `--limit` to snapshot** or remove from docs
4. **Improve extract reliability** — validate content field presence
5. **Add inline output option for extract** — reduce friction

### What Worked Well
- `extract` command is genuinely powerful (when it returns data)
- `eval` provides flexible JS-based extraction
- `goto` with URL-based search is a reliable workaround
- Snapshot format with refs is well-designed
- Server auto-start on first `open` call is seamless
- Documentation in SKILL.md is thorough and well-organized

### Overall Usability Rating: **6/10**

The CLI has a solid conceptual foundation and powerful features (`extract`, `eval`, snapshots). However, **session persistence flakiness** and **silent failures** in key commands significantly degrade the first-time user experience. A new user attempting the task as documented (form interaction via snapshots) would likely fail or give up. Power users who learn the workarounds (URL-based navigation, `eval` for extraction) can be productive, but the learning curve is steeper than it should be.

The most impactful single fix would be resolving the session state reliability issue — it affected nearly every interactive step in this evaluation.
