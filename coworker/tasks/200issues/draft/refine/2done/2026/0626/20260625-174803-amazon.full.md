## C. Issues Found

### Issue 1: `extract` Command Unusable for Complex Pages

**Severity:** Critical  
**Category:** Reliability  

**Reproduction:**
1. Navigate to `https://www.amazon.com/s?k=pens+to+draw+on+whiteboards`
2. Run `browser4-cli extract "Extract the first 4 search results"`

**Expected Behavior:** Returns structured data within a reasonable time (under 60s).

**Actual Behavior:** HTTP timeout after 30s (npm-installed CLI) or 180s (cargo-built CLI). The server-side processing never completes for Amazon-sized pages.

**Suggested Improvement:** 
- Implement chunked/streaming extraction for large pages
- Allow configurable timeout per-command (env var `BROWSER4_CLI_AGENT_TIMEOUT_SECS` exists but isn't in documentation)
- Provide a lighter-weight extraction mode for search result pages
- Consider client-side evaluation as a fallback

---

### Issue 2: No `search` Command or Documented Search Workflow

**Severity:** Medium  
**Category:** Discoverability / UX  

**Reproduction:**
1. As a new user, try to search on a website
2. Look for a `search` command in help output

**Expected Behavior:** A documented search workflow or a dedicated command like `browser4-cli search "<query>"`.

**Actual Behavior:** No `search` command exists. The multi-step workflow (snapshot → find searchbox ref → fill ref → press Enter) must be discovered through trial and error. This is the most common web interaction.

**Suggested Improvement:**
- Add a `browser4-cli search "<query>"` command that finds the page's search input by heuristic (role=searchbox, common names) and submits
- At minimum, document the search workflow pattern prominently in SKILL.md

---

### Issue 3: Snapshots Too Large for Usable Element Discovery

**Severity:** High  
**Category:** UX  

**Reproduction:**
1. Navigate to any content-rich page (e.g., Amazon search results)
2. Run `browser4-cli snapshot`
3. Read the resulting YAML file

**Expected Behavior:** A concise, scannable element tree focused on interactive elements.

**Actual Behavior:** The snapshot for Amazon search results was 1227 lines. With `-i` (interactive only), it was still large due to navigation menus, carousels, and footer elements. Finding the 4 product result refs required manually scrolling through hundreds of lines.

**Suggested Improvement:**
- Add a `--depth` default that excludes deeply nested hidden content
- Add a `--filter="role:link,role:button"` flag to filter by role
- Provide a `browser4-cli find "<text>"` command for ref discovery
- Auto-group carousel/sidebar content under collapsible headings in snapshot output
