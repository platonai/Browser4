## C. Issues Found

### Issue #1: `snapshot` output is file-only, never printed to stdout

- **Severity:** Medium
- **Category:** UX
- **Reproduction:** Run any `snapshot` command — it always writes to a file and only prints the file path.
- **Expected:** Snapshot content should be optionally printable to stdout (e.g., `--stdout` flag), or at minimum there should be a `show` command for the most recent snapshot.
- **Actual:** User must open the YAML file separately (`head`, `cat`, etc.), which contradicts the documentation's "Never cat full snapshot files" advice.
- **Suggested Improvement:** Add `--stdout` flag to `snapshot` or provide a `snapshot show` command that prints the last snapshot. For large pages, this could automatically apply `-i` and depth/limit defaults.

---

### Issue #2: Documentation inconsistency — `domsnapshot get all` vs `domsnapshot-get-all`

- **Severity:** High
- **Category:** Documentation
- **Reproduction:** Read SKILL.md line 228: `browser4-cli domsnapshot get all <field> [selector]`. Run that command — it fails with `Error: Unknown field 'all'`.
- **Expected:** Documentation should match the actual CLI interface.
- **Actual:** The actual command is `domsnapshot-get-all` (kebab-case subcommand), not `domsnapshot get all` (space-separated subcommand with "all" argument).
- **Suggested Improvement:** Update SKILL.md to use `domsnapshot-get-all` consistently. Also consider supporting `domsnapshot get all` as an alias for better discoverability.

---

### Issue #3: `domsnapshot-get-all` not implemented on server

- **Severity:** Critical
- **Category:** Product / Reliability
- **Reproduction:** Run `domsnapshot-get-all text "h2 span" --limit 10`. Returns `ERROR: Unknown tool: dom_snapshot_scrape_all`.
- **Expected:** The command should work as documented and extract all matching elements.
- **Actual:** Server-side tool `dom_snapshot_scrape_all` doesn't exist in the running server version.
- **Suggested Improvement:** Implement the `dom_snapshot_scrape_all` server endpoint, or if it's been renamed, update the CLI to call the correct endpoint.

---

### Issue #4: `domsnapshot get` returns empty strings silently

- **Severity:** Medium
- **Category:** UX / Reliability
- **Reproduction:** Run `domsnapshot get text "div[data-component-type='s-search-result'] h2 a span"` — returns `""`.
- **Expected:** If no element matches, the tool should return a clear message like "No element matches selector" or return a non-zero exit code.
- **Actual:** Returns an empty string with no error, leaving the user uncertain whether the tool worked, the selector was wrong, or the page structure changed.
- **Suggested Improvement:** Distinguish between "element found but no text content" and "no element matched" in output. Use stderr for diagnostics.

---

### Issue #5: `extract` output goes to file, not stdout

- **Severity:** Low
- **Category:** UX
- **Reproduction:** Run `extract "get product titles"` — output written to a `.txt` file in `.browser4-cli/snapshot/`.
- **Expected:** For non-batch use, users likely expect the extracted data to appear directly in the terminal after waiting for AI processing.
- **Actual:** Output goes to a file that must be opened separately. The CLI only prints the file path.
- **Suggested Improvement:** Add a `--stdout` flag to `extract` (and `snapshot`) to print results to stdout. Could also print a preview/summary inline and full content to file.

---

### Issue #6: No `--stdout` flag on any data-output commands

- **Severity:** Medium
- **Category:** UX / Discoverability
- **Reproduction:** Check `snapshot`, `extract`, `get`, `domsnapshot get` — none offer a way to print results to stdout.
- **Expected:** Common CLI pattern: data commands should support `--output -` or `--stdout` for piping and inline viewing.
- **Actual:** Every data extraction command requires an extra step to read the output file.
- **Suggested Improvement:** Add `--stdout` to `snapshot`, `extract`, `domsnapshot get`, `domsnapshot export`, etc.

### Issue #7: `extract` LLM dependency not transparent

- **Severity:** Low
- **Category:** Documentation / Discoverability
- **Reproduction:** Run `extract "..."` without configuring any LLM API key. It worked for me (server had a key pre-configured), but a first-time user may hit a silent or confusing failure.
- **Expected:** The documentation should explain what LLM providers are supported, how to configure keys, and what error to expect if keys are missing.
- **Actual:** SKILL.md says "Requires LLM API key configured" with a pointer to `references/agent.md`, but the error behavior when unconfigured is not documented.
- **Suggested Improvement:** Document the exact error message users will see without a configured key, and add an `extract --check-config` or `status` command that reports whether AI features are available.
