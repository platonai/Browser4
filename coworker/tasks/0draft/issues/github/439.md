# `fill` command fails with CSS selectors in direct mode but works in batch

URL: https://github.com/platonai/Browser4/issues/439
State: OPEN
Author: galaxyeye
Labels: bug, CLI, critical, reliability
Created: 06/19/2026 22:19:02
Updated: 06/19/2026 22:19:02


## Summary
The `browser4-cli fill` command fails with a `"No node with given id found"` error when invoked directly with a CSS selector, but the same command works correctly inside `batch` mode. This creates a confusing inconsistency where a basic user workflow (filling a single form field) is broken while the more complex batch workflow works.

## Steps to Reproduce
1. Run a standalone fill command with a CSS selector:
   ```
   browser4-cli fill "#first-name" "Alice"
   ```

## Expected Behavior
The text `"Alice"` should be filled into the `#first-name` input field, matching the behavior seen in batch mode.

## Actual Behavior
Error: `ERROR: browser_type failed: No node with given id found`

## Workaround
The same command works inside batch mode:
```
browser4-cli batch "fill #first-name 'Alice'"
```

## Suggested Fix
Unify CSS selector resolution between direct and batch command execution paths. Two possible approaches:
- The `browser_type` backend tool should accept CSS selectors consistently in both modes.
- The CLI should resolve CSS selectors to accessibility refs before dispatching to the backend.

## Impact
This is a critical bug that blocks the most basic usage pattern of the CLI — filling a single field. New users encountering this will likely assume the tool is broken rather than searching for a workaround.
