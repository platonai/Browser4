# `get text <ref>` returns help output on stale refs instead of a clear error

URL: https://github.com/platonai/Browser4/issues/440
State: OPEN
Author: galaxyeye
Labels: bug, medium, reliability, UX
Created: 06/19/2026 22:19:04
Updated: 06/19/2026 22:19:04


## Summary

When a user tries to use `browser4-cli get text <ref>` with a stale or invalid element reference, the command outputs the full help text rather than a specific, actionable error message. This makes it appear that the command syntax was wrong rather than the ref being stale.

## Steps to Reproduce

1. Navigate to a page (refs are assigned)
2. Perform an action that changes page state (click, navigate)
3. Try `browser4-cli get text <old-ref>`

## Expected Behavior

An error message like "Ref e12509 not found on current page" or "Stale ref -- take a fresh snapshot."

## Actual Behavior

The command outputs the full help text, which is confusing and misleading. Users are left wondering whether the command syntax was incorrect rather than understanding that the ref is no longer valid.

## Suggested Improvement

Detect stale or invalid refs and produce a specific, actionable error message. Falling through to the help output for invalid refs is misleading and harms the user experience.
