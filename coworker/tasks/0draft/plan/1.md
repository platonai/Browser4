# Browser4 Runtime Bundle Design

## Overview

Browser4 adopts a two-process architecture:

```text
browser4-cli (Rust)
        |
        +---- manages ----> browser4-server (Java)
```

The CLI is responsible for:

* installation
* upgrade
* startup
* shutdown
* health check
* version management

The server is distributed as a self-contained Runtime Bundle.

The bundle contains:

```text
runtime/
lib/
bin/
conf/
```

No system Java installation is required.

---

# Design Goals

## Primary Goals

1. No dependency on system JAVA_HOME
2. No administrator privileges required
3. Support self-upgrade
4. Support multiple versions
5. Fast startup
6. Small distribution size
7. Compatible with Spring Boot
8. Compatible with future Native Image migration

---

# Bundle Format

The server distribution artifact is:

```text
browser4-bundle-${version}.zip
```

Example:

```text
browser4-bundle-4.10.0.zip
```

Contents:

```text
browser4-server/

├── runtime/
│   ├── bin/
│   ├── lib/
│   └── ...
│
├── lib/
│   ├── browser4-server.jar
│   ├── spring-boot-*.jar
│   ├── jackson-*.jar
│   └── ...
│
├── bin/
│   ├── start.sh
│   └── start.bat
│
├── conf/
│   └── application.properties
│
└── VERSION
```

# Runtime Generation

Runtime is generated using jlink.

Example:

```bash
jlink \
  --add-modules java.base,java.logging,java.net.http \
  --strip-debug \
  --no-header-files \
  --no-man-pages \
  --compress=2 \
  --output runtime
```

Requirements:

* use jdeps to discover modules
* avoid ALL-MODULE-PATH
* minimize runtime size

---

# Application Packaging

Do NOT use Spring Boot Fat Jar.

Do NOT use:

```bash
java -jar app.jar
```

Use:

```bash
java -cp "lib/*"
```

Layout:

```text
lib/

browser4-server.jar
spring-*.jar
jackson-*.jar
...
```

Advantages:

* faster updates
* smaller patch size
* easier debugging
* traditional JVM deployment model

# Local Installation Layout

Browser4 uses:

```text
~/.browser4
```

as the root directory.

Layout:

```text
~/.browser4/

runtime/
│
├── current
│
└── versions/
    ├── 4.10.0/
    ├── 4.11.0/
    └── ...

data/

cache/

logs/

downloads/

conf/
```

Description:

| Directory | Purpose                   |
| --------- | ------------------------- |
| runtime   | Installed runtime bundles |
| data      | Persistent user data      |
| cache     | Temporary cache           |
| logs      | Runtime logs              |
| downloads | Download cache            |
| conf      | User configuration        |

---

# Version Management

Each version is stored independently.

Example:

```text
~/.browser4/runtime/versions/

├── 4.10.0/
└── 4.11.0/
```

Current active version:

```text
~/.browser4/runtime/current
```

Linux/macOS:

```text
symbolic link
```

Windows:

```text
directory copy or junction
```

Example:

```text
current -> versions/4.10.0
```

# Installation Workflow

Command:

```bash
browser4-cli install
```

Workflow:

```text
check runtime

    ↓

download bundle zip

    ↓

verify checksum

    ↓

extract to:

runtime/versions/{version}

    ↓

create/update current

    ↓

installation completed
```

---

# Startup Workflow

Command:

```bash
browser4-cli open
```

Workflow:

```text
check current runtime

    ↓

if missing

    ↓

auto install

    ↓

start server

    ↓

health check

    ↓

open browser
```

---

# Upgrade Workflow

Command:

```bash
browser4-cli upgrade
```

Workflow:

```text
download new version

    ↓

extract to runtime/versions/{version}

    ↓

start validation instance

    ↓

health check

    ↓

switch current

    ↓

remove old versions
```

# CI/CD Output

Build command:

```bash
./mvnw clean package -Pbundle
```

Output:

```text
target/browser4-bundle-${version}.zip
```

Bundle contains:

```text
runtime/
lib/
bin/
conf/
VERSION
```

No source code.

No tests.

No Maven repository.

No build cache.

---

# Future Compatibility

The CLI abstraction should not depend on the implementation technology.

Future runtime may be:

```text
Current:

jlink runtime
+
classpath jars

Future:

native-image executable
```

CLI behavior remains unchanged:

```bash
browser4-cli install
browser4-cli open
browser4-cli upgrade
browser4-cli stop
browser4-cli status
```

Only the bundle contents change.
