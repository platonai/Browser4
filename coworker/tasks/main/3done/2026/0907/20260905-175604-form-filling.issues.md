### Issue 1: Interaction commands silently scroll the page, so a later `snapshot -v 0` is not the page top — no doc note explains this

**Severity:** Medium
**Category:** Documentation

#### Reproduction

1) ./b4w.ps1 goto http://localhost:18080/generated/form-filling.html
2) Fill the form fields, then ./b4w.ps1 click <submit-ref> where the button is below the fold (y~1573 on this fixture).
3) ./b4w.ps1 snapshot -v 0 and inspect the output header.

#### Expected Behavior

The documentation and quick patterns should state that click/fill/select/check auto-scroll the element into view, so `-v 0` (scroll-relative 'current visible screen') after interactions starts mid-page — and an outcome-documentation capture should scroll to top first or use `-v all`.

#### Actual Behavior

After the below-fold click, `snapshot -v 0` reported 'hiddenTopHeight: 1057px' and stderr noted 'Page is scrolled 1057px down - this snapshot starts below the page top'. A controlled test confirmed -v 0 tracks real scroll: window.scrollTo(0,700) made the next -v 0 file report 'hiddenTopHeight: 700px'. SKILL.md's core-loop/quick patterns ('click submit -> wait --load networkidle -> snapshot -v 0 --auto-diff') and task briefs ('full-viewport snapshot (-v 0)') present -v 0 as if it were a stable top-of-page capture; nowhere is the auto-scroll side effect of interaction commands documented.

#### Root Cause Analysis

Interaction commands scroll elements into view (observed final scroll offset ~1057px equals centering the y~1573 button in a 1080px viewport). Viewport indices are deliberately scroll-relative (documented in help), but the documentation set does not connect the two facts, so first-time users/briefs assume -v 0 always means 'top of the page'. The CLI does print a corrective notice, but it arrives at the very end of the tips block, after the preview output.

#### Code Pointer

`skills/browser4-cli/SKILL.md (Core Loop + snapshot-mode table); cli/browser4-cli/src/main.rs (viewport-state notice emission)`

#### AI Suggested Improvement

- Add a documentation note to SKILL.md/snapshot.md and to the snapshot help: click/fill/select/check may auto-scroll the page; after any interaction `-v 0` is the current screen, not the page top.
- Update the 'Interactive Form Fill' and 'Verifying Results' quick patterns to include a scroll-to-top step (eval window.scrollTo(0,0)) or `snapshot -v all` before the final verification capture.
- Move the 'Page is scrolled N px down' notice earlier in the output (it currently trails the snapshot preview and is easy to miss in agent traces).

The command used to verify a page after an interaction ('Use get text or get attr to verify') should be discoverable from SKILL.md's command map / extraction decision tree, with its capture-free live-DOM semantics and its caveats documented.

### Issue 3: Hidden (display:none) form controls appear as addressable textbox refs in snapshot output with no visibility marker

**Severity:** Medium
**Category:** Product

#### Reproduction

1) ./b4w.ps1 goto http://localhost:18080/generated/form-filling.html (contact method defaults to Email).
2) ./b4w.ps1 snapshot -i (or snapshot / snapshot -v 0) and inspect the dynamic-fields section.

#### Expected Behavior

Form controls that are not visible on the page (display:none) should either be excluded from the accessibility snapshot or explicitly marked hidden, so an agent cannot target a field no user can see. At minimum the interactive-oriented rendering (-i) should not present them as self-contained targets.

#### Actual Behavior

The phone-number and company textboxes (wrappers hidden via .hidden { display:none !important } while contact method = email) appear in the snapshot with full refs - e.g. 'textbox "tel phone-number phoneNumber +1 555 123 4567" [ref=e1943]' - in default, -i and -v 0 captures. They carry no coordinates ([box=] absent) and no [hidden]/[invisible] marker; nothing in the docs explains that boxless means not visible. A first-time agent could confidently `fill e1943` a field that is invisible to the user (the fixture only reveals it when the Phone radio is chosen).

#### Root Cause Analysis

The snapshot builder emits addressable nodes for controls whose geometry is absent (display:none nodes reach the tree but have no bounding box). The -i interactive pass merges text into names but performs no visibility filtering, contradicting its 'each ref line reads as a self-contained target' description. Exact renderer location needs follow-up: the AX-tree-to-YAML generator is server-side and was not located in this pass (CLI-side viewport-state rendering lives in cli/browser4-cli/src/main.rs).

#### Code Pointer

`Server-side AX snapshot/YAML renderer (module not located; search for the emitter producing 'textbox ... [ref=e...]' YAML lines in browser4-core/browser4-browser), CLI viewport headers in cli/browser4-cli/src/main.rs`

#### AI Suggested Improvement

- Mark nodes with no bounding box as [hidden] (or omit them) in snapshot output, and filter them from the -i interactive-oriented rendering.
- If kept, document the convention 'elements without [box=...] are not visible' in snapshot.md.
- Add a regression test: hidden dynamic form fields (display:none toggled by JS) must not be emitted as fillable targets in -i mode.

### Issue 4: Shared DEFAULT session is silently reused across concurrent invocations, letting one process clobber another's page

**Severity:** Low
**Category:** UX

#### Reproduction

1) With a backend running and a DEFAULT session active on another page, run ./b4w.ps1 goto http://localhost:18080/generated/form-filling.html from a second process.

#### Expected Behavior

Concurrent/automated invocations should either get isolated state or a clear warning that they are hijacking an in-use session, since navigation replaces the other process's page.

#### Actual Behavior

goto printed 'Using existing session DEFAULT (current page: http://localhost:18080/ec/dp/B0E000002)' - a page left open by a different concurrent evaluation process - and navigated that shared session to the form page, invalidating the other process's page state. The reuse message is easy to miss mid-script, and nothing in the session documentation calls out this hazard for parallel agent usage.

#### Root Cause Analysis

The unnamed DEFAULT session is a singleton shared by every invocation that omits -s; goto auto-reconnects to it by design (persistence is desirable for interactive use). The design has no concurrency awareness - no lock, no warning that the session's current page belongs to another recent process.

#### Code Pointer

`cli/browser4-cli/src/main.rs (session selection / reuse logic); skills/browser4-cli/SKILL.md section 2 Sessions`

#### AI Suggested Improvement

- Add a SKILL.md callout: parallel agent runs should always pass `-s <name>`; the DEFAULT session is shared and last-writer-wins.
- Consider warning on goto when reusing a session whose current page differs from the requested URL and whose last activity is recent.
- Optionally support an opt-in per-invocation anonymous session (e.g. config or env var) for scripted/parallel use.

#### Expected Behavior

Default behavior favoring ref freshness is fine, but the output and cost overhead of the automatic snapshot should be lighter (single line when the page is unchanged), with cleanup guidance nearby.

#### Actual Behavior

Each of the ~10 interaction commands printed a repeated '### Page / URL / Title / ### Snapshot / [link] / size' block and wrote a new snapshot file (~13 files in a 2-minute session). #### Root Cause Analysis

The auto-snapshot design trades efficiency for ref reliability and prints the full capture summary unconditionally after every interaction; the snapshot-directory growth has a cleanup command (`snapshot clean`) that is documented only in the help list, not in SKILL.md.

#### Code Pointer

`cli/browser4-cli/src/main.rs (post-interaction auto-snapshot printing)`

- Print a one-line auto-snapshot summary (refs refresh + file link) instead of the repeated page header block when the page URL/title are unchanged.
- Mention --no-snapshot and `snapshot clean` (or a retention policy) in the interaction command help / SKILL.md so users can opt out of both noise and file growth.
