# Search query duplicated due to timeout / silent execution

## Summary

When a `type` command times out but actually executes silently, a subsequent `type` command appends the same text again. This results in a duplicated search query — the text appears twice, concatenated in the search field.

## Steps to reproduce

1. Run `browser4-cli type "pens to draw on whiteboards" e37` on a search box. Wait for the timeout.
2. Run `browser4-cli type "pens to draw on whiteboards"` (or with a ref) again.
3. Submit the search and observe the resulting search URL.

## Expected behavior

The search query appears exactly once in the search URL.

## Actual behavior

The search URL contains the query duplicated, e.g., `k=pens+to+draw+on+whiteboardspens+to+draw+on+whiteboards`. This is a direct consequence of the `type` command silently executing despite reporting a timeout.

## Suggested resolution

- Fix the root cause: ensure the `type` command either reliably reports success/failure or uses a verify-after-timeout mechanism.
- As a defense-in-depth measure, the `type` command could clear the field before typing, or `fill` could replace content rather than append.
- Consider implementing an idempotency check: if the field already contains the target text, skip the operation.
