## Summary

The evaluation instructions and SKILL.md reference `cargo run` as a way to interact with the project, but the primary distribution method is npm. The project mixes Rust (native binary) and npm (distribution wrapper) in a way that is confusing for new users, who will be unclear whether this is a Rust project or a Node.js project.

## Steps to Reproduce

The evaluation instructions say to run `cargo run -- help`. SKILL.md mentions "Installs the native Rust binary" but the primary installation method is npm.

## Actual Behavior

A new user reading the documentation would be confused about the project architecture. The `Cargo.toml` exists in a parent directory and is only used for build steps, but the instructions suggest using `cargo run` directly. This creates an unclear mental model of how the project is built and distributed.

## Suggested Improvement

Clarify the architecture in the documentation:
- browser4-cli is a Rust binary distributed via npm
- For development, use `npm run build:native`, not `cargo run`
- For usage, `browser4-cli` is the only command needed
- The `Cargo.toml` location and its relationship to the npm package should be explained
