# browser4 ignores envs (`OPENAI_*`), configs and routes to default provider

URL: https://github.com/platonai/Browser4/issues/609
State: OPEN
Author: nielsonsantana
Created: 09/26/2026 11:17:20
Updated: 09/28/2026 03:20:13

First, I would like congrats for this amazing work. I have had some issues about use browser4 with custom providers.

**Bug description**
I'm trying to use DeepInfra as an OpenAI-compatible provider. `browser4-cli doctor` says "LLM is configured", but
every LLM request goes to the DeepSeek default instead of DeepInfra. `summarize` runs but hits the wrong endpoint.

Tried three ways, none worked:
1. Env only — `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL_NAME`
2. Config file only — `~/.browser4/config/conf-enabled/application-private.properties` with
`openai.api.key`, `openai.base.url`, `openai.model.name`
3. Both together

In every case backend said key configured but routed to DeepSeek default.

**Config used**
```
openai.api.key=<valid deepinfra key>
openai.base.url=https://api.deepinfra.com/v1/openai
openai.model.name=deepseek-ai/DeepSeek-V4.1-Flash
```
Key + model verified valid against DeepInfra (`/models` → 200, model listed).

**Observed**
- `browser4-cli doctor --verbose` → `✓ LLM is configured`, `Configured keys: OPENAI_API_KEY`,
`Source: configuration file`.
- Whether base-url/model set via env or config, `summarize` never targets `https://api.deepinfra.com/v1/openai`.
- `openai.base.url`/`openai.model.name` (and env forms) appear ignored; falls back to
`deepseek-v4-flash` / `api.deepseek.com`.

**Environment**
- Browser4 CLI: 4.13.22
- Backend: 4.13.22-SNAPSHOT (dev snapshot)
- OS: Linux ( ubuntu 24.04)
