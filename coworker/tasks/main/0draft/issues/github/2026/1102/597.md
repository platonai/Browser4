# uninstall does not remove the skills that install copied into ~/.agents/skills

URL: https://github.com/platonai/Browser4/issues/597
State: OPEN
Author: platonai
Labels: enhancement, CLI, low
Created: 09/16/2026 16:14:19
Updated: 09/16/2026 16:14:19

## Summary

`install` / `upgrade` copy the bundled skills into `~/.agents/skills` for AI agents to pick up, but `uninstall` never removes them. After a complete uninstall the agent still discovers the Browser4 skills and keeps selecting them, even though every command they reference is gone.

## Observed

`browser4-cli install` reports the sync:

```
📦 Unpacked 39 skill files to %APPDATA%\browser4\runtime\v4.13.19\skills
🤖 Installed 39 skill files for AI agents to %USERPROFILE%\.agents\skills
```

`browser4-cli uninstall --dry-run` enumerates everything it intends to delete — the agents skills directory is not part of it:

```
🔍 Would remove runtime data directory: %APPDATA%\browser4
🔍 Would remove runtime cache directory: %LOCALAPPDATA%\browser4
ℹ  ...
   🔍 Would attempt to remove the binary.
```

The real run (`uninstall -y`) never mentions skills either, and the directories survive.

## Evidence in the code

In `cli/browser4-cli/src/main.rs` (branch `4.13.x`) the agents-skills sync exists only on the install and upgrade paths:

- `skills::agents_skills_dir()` — `src/skills.rs:132`, resolves `~/.agents/skills` (override: `BROWSER4_AGENTS_SKILLS_DIR`, `src/skills.rs:124-153`)
- **install** path — `main.rs` ~L16064-16141 (`agents_skills_dir`, `format_agents_skills_sync_message`, `agents_skills_files_unpacked`)
- **upgrade** path — `main.rs` ~L17863-17868

`grep -n "agents_skills\|\.agents\|BROWSER4_AGENTS_SKILLS_DIR" cli/browser4-cli/src/*.rs` returns hits only in `skills.rs`, `help.rs`, and the two sync sites above — nothing inside `handle_uninstall` (`main.rs` ~L17094).

There is also no user-facing way to remove them short of deleting the directories by hand: `skill-uninstall` targets the server-side skill registry, not this directory.

## Why it matters

Install → uninstall leaves behind skills that advertise a CLI which no longer exists. An agent that loads them will follow instructions for `browser4-cli …` commands and fail on every step, with no hint that the tool is gone. It also makes "uninstall" non-idempotent from the user's point of view: the machine still looks like it has Browser4 installed.

## Proposal

Mirror the install-side sync on uninstall: remove the skill directories that `install` created for the bundled set (`browser4-cli`, `browser4-experience`, `browser4-plugin`, `browser4-web-miner`) — or, if removing a shared agents directory is considered too invasive, at least list them in the uninstall summary so the user can decide.

## Environment

- `browser4-cli` 4.13.19 (npm global install), Windows / PowerShell
- Same setup as #595
