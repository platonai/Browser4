# [Docs/CLI] Windows PowerShell 下 snapshot grep 的正则包含管道符时会被 shell 拆分，建议补充转义说明并提供 --pattern-file

URL: https://github.com/platonai/Browser4/issues/622
State: OPEN
Author: platonai
Created: 10/27/2026 01:42:42
Updated: 10/27/2026 01:42:42

## 环境

- OS: Windows（PowerShell）
- browser4-cli: 4.15.2-SNAPSHOT
- 会话: headless

## 问题描述

在 Windows / PowerShell 下执行 `snapshot grep` 时，如果正则里包含管道符（`|`），PowerShell 会把它当成自己的管道操作符，参数被拆开执行，CLI 收到的是残缺的片段，于是报出与 CLI 无关的 shell 错误：

```powershell
browser4-cli -s ext snapshot grep "Sign in|Add a title|Create"
```

实际输出：

```
title: 无法将“title”项识别为 cmdlet、函数、脚本文件或可运行程序的名称。
请检查名称的拼写，如果包括路径，请确保路径正确，然后再试一次。
[exit code: 1]
```

同一条命令去掉管道符之后就正常：

```powershell
browser4-cli -s ext snapshot grep "Add a title"
# 157: - textbox "Add a title" [ref=e13286] [box=335,193,958,30]
```

也就是说，模式里的 `|` 必须手工转义成 `\|` 或者换成单引号才能传进 CLI。对多分支正则（在含中英文界面、多种按钮文案的页面上很常用）来说，每次都要记得转义，写脚本时很容易踩坑。

## 期望

1. **文档补充**：在 Quick Reference / `skills/*.md` 的 “Shell quoting (Windows)” 小节里，把 `snapshot grep` 的 `|` 也列进已知坑，给出 PowerShell 下的正确写法。
2. **更好的方案**：像 `--sql @f.sql`、`eval --file` 那样，为 `snapshot grep` 增加 `--pattern-file <file>`（或 `--stdin`），让复杂正则可以放进文件，彻底绕开 shell 转义问题。

## 影响

影响所有在 Windows PowerShell 下用正则筛选快照的用户；由于 `snapshot grep` 是定位元素的第一步，踩坑时看到的报错信息（“无法将 xxx 项识别为 cmdlet”）和 CLI 完全无关，排查成本比较高。
