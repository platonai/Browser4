### Issue 1: b4w.ps1 fails on Linux due to CRLF line endings

**Severity:** High
**Category:** Reliability

#### Reproduction

./b4w.ps1 help

#### Expected Behavior

The PowerShell script should run on Linux when pwsh is installed.

#### Actual Behavior

/usr/bin/env: 'pwsh\r': No such file or directory. The shebang line contains a carriage return, making the script unexecutable on Linux.

#### Root Cause Analysis

b4w.ps1 has Windows-style CRLF line endings. On Linux, the kernel interprets the shebang as `pwsh\r` (with trailing carriage return) and cannot find an executable with that name. The file needs LF line endings.

#### Code Pointer

`b4w.ps1 — needs `git add --renormalize` or `.gitattributes` entry to enforce LF line endings for .ps1 files, or convert to LF manually.`

#### AI Suggested Improvement

- Add a `.gitattributes` rule: `b4w.ps1 text eol=lf` to force LF line endings on checkout
- Or convert b4w.ps1 to LF line endings in the repository
- The SKILL.md documentation correctly recommends b4w.sh for bash/Linux environments, which works around the issue

### Issue 2: eval returns inconsistent results for the same page context

**Severity:** High
**Category:** Reliability

#### Reproduction

Run the same JavaScript eval twice on an Amazon search results page:
1. First eval: `document.querySelector('h2 a')` returns titles
2. Second eval: Same query returns empty strings for titles and URLs
Observed across four eval calls on the same page without navigation between them.

#### Expected Behavior

Repeated eval calls on the same page should return consistent results for the same DOM queries.

#### Actual Behavior

The first product extraction eval returned all four titles successfully. Subsequent eval calls (for URLs, reviews, combined extraction) returned empty strings for titles and URLs — even though price and rating data were still extracted. The last eval attempt returned titles in one run and empty strings in the next, suggesting non-deterministic behavior.

#### Root Cause Analysis

Unclear. Possible causes: (1) Amazon's page dynamically modifies the DOM between eval calls (A/B testing, lazy loading, ad injection). (2) The eval execution context differs between calls (iframe vs main frame). (3) A race condition where eval executes before the page fully stabilizes after the previous command. Further investigation needed.

#### AI Suggested Improvement

- Add a `--wait-selector` flag to eval (mentioned in help) to ensure target elements are present before executing
- Document that eval may return partial results on dynamic pages and recommend htmlsnapshot for extraction
- Add built-in retry capability for eval when expected elements are missing
- Investigate whether each eval call shares the same execution context or creates a new one

- Improve the default output by collapsing consecutive `generic` wrappers with no semantic role
- The existing `-i` mode exists but docs warn it strips generic divs which may hide product cards on e-commerce pages
