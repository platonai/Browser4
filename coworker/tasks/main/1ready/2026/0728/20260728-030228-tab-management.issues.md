### Issue 1: PowerShell -v flag interception makes snapshot -v 0 fail with b4w.ps1

**Severity:** High
**Category:** UX

#### Reproduction

./b4w.ps1 snapshot -v 0

#### Expected Behavior

Snapshot captured with viewport 0 (top of page).

#### Actual Behavior

Error: Unknown command: 'snapshot-0'. Did you mean: 'snapshot'? The -v flag was consumed by PowerShell as -Verbose, leaving '0' appended to 'snapshot'.

#### Root Cause Analysis

PowerShell's parameter binder matches -v to its built-in -Verbose common parameter before the script's $RemainingArgs collection receives it. The script uses [Parameter(ValueFromRemainingArguments = $true)] which only collects arguments not matched by any declared parameter, but -v matches -Verbose.

#### Code Pointer

`b4w.ps1: the param() block and how RemainingArgs is forwarded to cargo run`

#### AI Suggested Improvement

- Add a -v shorthand param to b4w.ps1 that explicitly passes it through to the CLI (e.g., [switch]$v plus manual argument reconstruction)
- Or document prominently that Linux/bash users should prefer b4w.sh, and explain why
- Fix the documented -- separator workaround (currently broken: 'Parameter name '' is ambiguous')
- Consider detecting pwsh version and warning about known parameter binding conflicts

- [ ] **REJECT** — issue invalid, not a problem, or already addressed
- [ ] **DUPLICATE** — issue duplicates another existing issue (reference in Notes)
- **Notes:**
[AI suggested: ACCEPT] Real platform-specific bug — PowerShell's parameter binder greedily matches `-v` to `-Verbose` before `$RemainingArgs` sees it. This blocks legitimate CLI usage on Windows. Fix should add an explicit `[switch]$v` param in `b4w.ps1` that manually forwards to the CLI, or detect and warn about the interception.

### Issue 2: Documented -- separator workaround for b4w.ps1 doesn't work

**Severity:** High
**Category:** Documentation

#### Reproduction

./b4w.ps1 -- snapshot -v 0

#### Expected Behavior

The -- separator should pass snapshot -v 0 through to the CLI.

#### Actual Behavior

PowerShell error: 'Parameter cannot be processed because the parameter name '' is ambiguous. Possible matches include: -Rebuild -RemainingArgs -Verbose ...'

#### Root Cause Analysis

The b4w.ps1 param block declares [Parameter(ValueFromRemainingArguments = $true)] which doesn't interact correctly with -- when the script itself is the target. PowerShell's -- separator only works for native commands, not script parameters.

#### Code Pointer

`b4w.ps1: param() declaration and argument forwarding logic`

#### AI Suggested Improvement

- Either fix b4w.ps1 to properly handle -- separator by parsing it before the param block
- Or update the SKILL.md documentation to remove this as a recommended workaround since it doesn't work
