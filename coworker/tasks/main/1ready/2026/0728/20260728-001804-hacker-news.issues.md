### Issue 1: b4w.ps1 parameter binding fails on Linux — `--` passthrough documented but broken

**Severity:** High
**Category:** Reliability

#### Reproduction

Run `./b4w.ps1 -- goto "https://news.ycombinator.com/news"` from bash on Linux with pwsh 7 installed.

#### Expected Behavior

The `--` separator should pass all remaining arguments through to the CLI binary without PowerShell interpreting them.

#### Actual Behavior

PowerShell reports: 'Parameter cannot be processed because the parameter name '' is ambiguous. Possible matches include: -Rebuild -RemainingArgs -Verbose -Debug...' The command fails entirely.

#### Root Cause Analysis

When invoked via `pwsh -NoProfile -File b4w.ps1`, the script's `param()` block processes `--` as a parameter name candidate. The b4w.ps1 script has logic to strip `--` (line 61-68) but the error occurs before the script body executes — PowerShell's parameter binder rejects the ambiguous token at parse time. The `-File` invocation mode triggers PowerShell's own parameter parsing of the script arguments, and `--` doesn't escape that layer.

#### Code Pointer

`b4w.ps1: the param() block and the passthrough logic at lines 60-68. The underlying issue is that `pwsh -File` pre-parses arguments before the script body runs.`

#### AI Suggested Improvement

- Document that on Linux, users MUST use `./b4w.sh` instead of `./b4w.ps1` — the `--` workaround only works from within a pwsh interactive session
- Consider detecting non-Windows in b4w.ps1 and printing a clear error directing users to b4w.sh
- Alternatively, fix the Linux install to create the `b4w` bash launcher automatically so users don't encounter this
