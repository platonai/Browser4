### Issue 1: Snapshot output is verbose even with -v 0 and lacks clear page identification

**Severity:** Medium
**Category:** UX

#### Reproduction

Run `./b4w.ps1 snapshot -v 0 --stdout` on a Wikipedia article. The output starts with viewport metadata then immediately dumps a deep accessibility tree.

#### Expected Behavior

The snapshot output should prominently display the page URL and title at the top for quick context verification, before the accessibility tree.

#### Actual Behavior

The viewport metadata block shows technical details (viewportHeight, viewportsTotal, hidden heights) but not the page URL or title. The user must separately reference tab-list or the previous goto output to confirm which page they're looking at. The accessibility tree starts with a deeply nested generic container, requiring significant scrolling to find actual page content.

#### Root Cause Analysis

The snapshot YAML output format focuses on the accessibility tree structure and viewport metadata. Page identification (URL/title) is shown by the goto command but is not included in snapshot output.

#### Code Pointer

`cli/browser4-cli/src/snapshot.rs — the snapshot rendering/formatting logic`

#### AI Suggested Improvement

- Include page URL and title in the snapshot header (e.g., '# Page: Web scraping - Wikipedia — https://en.wikipedia.org/wiki/Web_scraping')
- This would make standalone snapshots self-describing for context verification without needing to cross-reference tab-list

### Issue 2: Short flag warning on b4w.ps1 contradicts documentation and itself

**Severity:** Low
**Category:** UX

#### Reproduction

Run `./b4w.ps1 snapshot -v 0 --stdout` from Linux/bash.

#### Expected Behavior

The SKILL.md states b4w.ps1 uses manual $args parsing so short flags are safe. The CLI should either not warn on b4w.ps1, or the warning should be accurate for the current context.

#### Actual Behavior

Every invocation produces: '⚠ Short flags detected: -v PowerShell may intercept these in other contexts (b4w.sh, direct pwsh). Prefer long-form equivalents: --output, --interactive, --viewport Or use b4w.sh / b4w.bat (cmd.exe) for full compatibility.' The warning says short flags may be intercepted in b4w.sh, then recommends b4w.sh as a fix — self-contradictory. The suggestion to use --output for -v is wrong (--viewport is the correct equivalent).

#### Root Cause Analysis

The warning is emitted unconditionally when short flags matching PowerShell common parameters are detected, regardless of which wrapper script is in use. When running via b4w.sh on Linux, the pwsh parameter binding issue doesn't apply, yet the warning fires anyway. The warning text also has a logic error in its recommendation chain.

#### Code Pointer

`cli/browser4-cli/src/main.rs or the b4w.ps1 script — wherever the short-flag detection and warning logic lives`

#### AI Suggested Improvement

- Detect which wrapper is in use and skip the warning when b4w.ps1 is the entry point (since it handles short flags correctly)
- Fix the contradictory recommendation: if b4w.sh may intercept flags, don't recommend it as a fix
- Correct the flag mapping: -v maps to --viewport, not --output

### Issue 3: Compilation output noise on every command

**Severity:** Low
**Category:** UX

#### Reproduction

Run any `./b4w.ps1` command. Every invocation prints 'Finished `dev` profile [unoptimized + debuginfo] target(s) in X.XXs' before the actual command output.

#### Expected Behavior

The compilation status line should be suppressed or shown only when a rebuild actually occurred. Alternatively, it could go to stderr so it doesn't pollute command output.

#### Actual Behavior

Every command starts with the cargo build status line, adding visual noise and making it harder to scan command output.

#### Root Cause Analysis

The b4w.ps1/b4w.sh wrappers run `cargo run` which always prints build status to stdout. There's no --quiet flag being passed to suppress it when nothing was rebuilt.

#### Code Pointer

`b4w.ps1 and b4w.sh wrapper scripts — the cargo run invocation`

- Pass `--quiet` to cargo run so the build status line only appears when there's an error or actual recompilation

### Issue 4: tab-new insertion position is surprising for new users

**Severity:** Low
**Category:** Discoverability

#### Reproduction

1. `tab-new url1` (creates tab 1). 2. `tab-new url2`. The second tab becomes index 1, pushing url1 to index 2, because Chrome inserts after the active tab.

#### Expected Behavior

A first-time user might expect tab-new to always append at the end (index 2), or the CLI to provide an option for append vs. insert-after-current behavior.

#### Actual Behavior

Tabs are inserted by Chrome after the active tab, which is documented in SKILL.md but still surprising during first use. The user must run tab-list to discover the actual ordering.

#### Root Cause Analysis

Browser4 delegates tab creation to Chrome's native CDP method, which inserts after the active tab per Chrome's default behavior. Browser4 does not reorder or reposition tabs after creation.

#### AI Suggested Improvement

- Add a brief note in the tab-new output indicating the insertion position (e.g., 'Inserted after current tab at index N')
- Consider adding a --position flag (start/end/after-current) if CDP supports it

### Issue 5: No visual feedback after tab-select beyond a one-line confirmation

**Severity:** Low
**Category:** UX

#### Reproduction

Run `tab-select 0`. Output: 'Switched to tab 0 (url)'. No snapshot or page preview is shown.

#### Expected Behavior

While the no-auto-snapshot behavior is documented, a first-time user might expect some lightweight page identification (title) after switching, or an optional --snapshot flag on tab-select to combine switch+verify in one command.

#### Actual Behavior

The user must always run a separate snapshot command after tab-select to verify the correct tab is active. This adds an extra command for every tab switch.

#### Root Cause Analysis

tab-select only activates the tab via CDP. It does not trigger any page content inspection. This is by design (documented) but adds friction for interactive tab-hopping workflows.

#### AI Suggested Improvement

- Add an optional `--snapshot` flag to `tab-select` that automatically captures a snapshot after switching
- Or at minimum print the page title alongside the URL in the 'Switched to tab N' message
