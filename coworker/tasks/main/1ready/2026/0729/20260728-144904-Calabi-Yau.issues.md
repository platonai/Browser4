### Issue 1: b4w wrapper argument passing broken in bash/Linux environment

**Severity:** Critical
**Category:** Reliability

#### Reproduction

./b4w.ps1 goto "https://www.amazon.com" or ./b4w.sh goto "https://www.amazon.com" from bash

#### Expected Behavior

Arguments 'goto' and 'https://www.amazon.com' should pass through to the browser4-cli binary.

#### Actual Behavior

The TopHelp text from b4w.ps1 is emitted, followed by the browser4-cli help text and 'Unknown command: —'. The binary never receives the correct arguments. The cargo output shows the entire help text being passed as arguments to the binary instead of 'goto' and the URL.

#### Root Cause Analysis

The b4w.sh script uses `exec pwsh -Command "& '$SCRIPT_DIR/b4w.ps1' $ARGS"` where $ARGS is individually quoted. The exec within a command substitution $(...) appears to cause argument corruption. Additionally, the b4w.ps1 script's $TopHelp heredoc contains em-dash characters ('—') that may trigger PowerShell string interpolation issues when combined with Invoke-Expression on line 478.

#### Code Pointer

`b4w.sh lines 34-51 and b4w.ps1 lines 470-488`

#### AI Suggested Improvement

- Add a direct bash-native launcher (e.g. b4w binary wrapper) that doesn't require PowerShell as an intermediary on Linux
- Fix b4w.sh to not use exec inside command substitution contexts
- Replace Invoke-Expression in b4w.ps1 line 478 with a direct call operator invocation (e.g. & $Exe @CliArgs) to avoid string interpolation issues with special characters
- Add a cargo alias or Makefile target so users on Linux can run `make run -- goto <url>` without wrestling with shell wrappers

**Category:** Reliability

#### Expected Behavior

After goto navigates to Amazon, the session should stay on Amazon until explicitly navigated elsewhere.

#### Actual Behavior

After successful goto to Amazon (confirmed by the CLI output showing 'Navigated to https://www.amazon.com'), subsequent commands (eval, htmlsnapshot) execute on Wikipedia instead. #### Root Cause Analysis

Investigation needed: check PulsarWebDriver session reconnection logic and whether goto properly updates the backend's session URL state before the CDP page load event fires.

#### Code Pointer

`browser4-core/browser4-browser/ — PulsarWebDriver session management and reconnection logic`

- Ensure goto atomically updates the session's canonical URL in the backend before the CDP navigation completes
- Add a post-navigation verification step that checks the actual page URL matches the requested URL
- Log a warning if the page URL changes unexpectedly between commands
- Document that pre-existing sessions may have stale state and recommend using fresh named sessions (-s <name>) for reliable automation
