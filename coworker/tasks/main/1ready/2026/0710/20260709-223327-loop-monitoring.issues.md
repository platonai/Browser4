## Issues Found (6 issues)
> **Review complete:** 0 approved, 6 deferred/rejected

### Issue 1: Plain-text loop tasks fail without a configured LLM

**Severity:** High
**Category:** Reliability

#### Review Result

**Decision:** WONTFIX

**Summary:** - Add a pre-flight validation before starting a plain-text loop: send a lightweight probe to the server to verify the agent command endpoint is responsive, and fail fast with a clear error if not.

---

### Issue 2: `--` separator incorrectly consumed by `parse_raw_args` before `build_command_args` rejects multi-token loop tasks

**Severity:** High
**Category:** Product

#### Review Result

**Decision:** WONTFIX

**Summary:** - In `parse_raw_args`, add special handling for bare `--` to stop option parsing and treat all remaining tokens as positional arguments (POSIX convention).

---

### Issue 3: Completed loops are auto-cleaned with no indication in `--list` output

**Severity:** Medium
**Category:** UX

#### Review Result

**Decision:** WONTFIX

**Summary:** - When `--list` finds no persisted loops, add a hint: "Use `browser4-cli loop --history` to see recently completed loops."

**Severity:** Medium

## How to Reproduce

### Common Setup

1. Clone the repository and `cd` to the repo root.
2. Build the CLI: `cd cli/browser4-cli && cargo build`
3. The backend server starts automatically in dev mode.
4. All commands from repo root: `cd cli/browser4-cli && cargo run -- <command>`

### Per-Issue Reproduction Steps

#### Issue 1: Plain-text loop tasks fail without a configured LLM

```
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- loop --count 2 --interval 10 --name health-check "Navigate to https://httpbin.org/get, take a snapshot, and report the page status"
```

#### Issue 2: `--` separator incorrectly consumed by `parse_raw_args` before `build_command_args` rejects multi-token loop tasks

```
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- loop --count 2 --interval 10 --name test -- batch "goto https://httpbin.org/get" snapshot status
```

#### Issue 3: Completed loops are auto-cleaned with no indication in `--list` output

1. Run `loop --count 2 --interval 5 --name my-test --shell "echo hello"`
2. Wait for completion (2 iterations finish)
3. Run `loop --list`

#### Issue 4: Loop completion message is misleading when all iterations failed

```
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- loop --count 2 --interval 10 --name health-check "Navigate to https://httpbin.org/get"
```
(Both iterations fail with HTTP timeout.)

#### Issue 5: `--shell` mode requires full path to browser4-cli binary for browser commands

A user wants to run browser4-cli commands in a loop. The `--` subcommand mode is the natural choice but fails for multi-command tasks (Issue 2). The `--shell` workaround requires knowing the compiled binary path:
```
loop --shell '/home/vincent/workspace/Browser4/cli/browser4-cli/target/debug/browser4-cli goto ... && .../browser4-cli snapshot && .../browser4-cli status'
```

#### Issue 6: `--help` for `loop` shows option names but lacks examples

Run `cargo run --manifest-path cli/browser4-cli/Cargo.toml -- loop --help` (or the equivalent).
