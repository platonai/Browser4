## What It Is

The **Wuhan Lobster Festival**, officially branded as the **"2026 Wuhan Crayfish Consumption Season" (2026武汉小龙虾消费季)**, is a large-scale, multi-month consumption promotion event organized by the **Wuhan Municipal Commerce Bureau** (武汉市商务局) in collaboration with the Municipal Science and Innovation Bureau and other departments. It is designed to:

- Extend the consumption momentum from Wuhan's spring cherry blossom season
- Leverage the May Day "Golden Week" holiday period
- Bridge through Dragon Boat Festival and summer vacation season
- Promote Wuhan's crayfish (小龙虾) food culture as a city brand and IP

The event frames crayfish as Wuhan's "summer-limited taste symbol" (夏日限定的味觉符号) and positions the city as an "international consumption center" (国际消费中心城市).

## History and Background

- **Origins**: Wuhan has long been known as China's "Crayfish City" (小龙虾之城). The formal, branded "Consumption Season" format began in recent years as a government-organized initiative, building on Wuhan's deep culinary tradition of crayfish dining and its position as China's largest crayfish consumption market.
- **2026 edition**: On April 21, 2026, the Commerce Bureau publicly solicited service platforms for distributing consumption vouchers. On April 28, the municipal government held a press conference to announce the event. The main venue carnival launched on April 30.
- **National context**: According to Meituan data, **Wuhan accounts for 41.9% of China's total crayfish consumption** — "out of every 10 crayfish sold in China, about 4 are consumed in Wuhan."
- **Supply chain**: Wuhan collaborates with **Qianjiang** (潜江), a major crayfish-producing region in Hubei, forming a "production + consumption" complementary model.

## Major Activities — Four Themed Series

The event is organized around four major series ("四大系列"):

1. **虾聚江城 (Crayfish Gathering Jiangcheng)** — Food-focused: crayfish food festivals, beer carnivals, crayfish markets, and promotion of famous dishes and restaurants. Features well-known local brands: 肥肥虾庄, 靓靓蒸虾, 巴厘龙虾, 一棠龙虾, 虾皇.

2. **展演江城 (Exhibition Jiangcheng)** — Integration of crayfish with exhibitions and events: Optics Valley Expo, Central China International Auto Show, Tea Expo, anime/gaming festivals, and sports event tie-ins (e.g., Chu Super League football).

3. **不夜江城 (Sleepless Jiangcheng)** — Nighttime economy: beer and music carnivals, Summer Solstice Music Day, summer lifestyle festivals, ice & fire parties, illustration art festivals, and multi-dimensional nighttime consumption scenarios.

4. **惠享江城 (Benefit Jiangcheng)** — Consumer incentives: **¥3 million in special crayfish consumption vouchers** distributed across 13 batches via Meituan (美团), Dianping (大众点评), and Douyin (抖音) from May 1 to July 31. Combined platform and merchant discounts, trade-in programs, and lucky invoice campaigns covering dining, shopping, accommodation, tourism, and entertainment.

### Issue 1: htmlsnapshot fails with JS injection error on Baidu Baike

**Severity:** High
**Category:** Reliability

#### Reproduction

```bash
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- goto "https://www.baidu.com"
# Search for something, click a Baike result
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- htmlsnapshot
```

#### Expected Behavior

HTML snapshot captured successfully, returning page metadata.

#### Actual Behavior

```
ERROR: html_snapshot_capture failed: ReferenceError: __pulsar_utils__ is not defined
    at <anonymous>:1:1
>>>__pulsar_utils__.getAnnotatedHTML()<<<
```

#### Root Cause Analysis

The JavaScript bridge object `__pulsar_utils__` is not being injected or is being blocked on certain pages (specifically Baidu Baike). This may be due to the page's Content Security Policy (CSP), script injection timing, or the page's own JavaScript interfering with the injection mechanism.

#### Code Pointer

``cli/browser4-cli/src/http.rs` or the backend's JavaScript injection/evaluation path.`

#### AI Suggested Improvement

- Add a fallback mechanism when `__pulsar_utils__` is unavailable — retry injection or fall back to `eval`-based DOM serialization
- Improve error message to tell users what to do instead (e.g., "Use `snapshot -v 0` for accessibility tree or `eval` for custom JS extraction")
- Detect CSP restrictions and report them explicitly in the error message

### Issue 2: Off-screen element clicking silently fails with misleading message

**Severity:** Medium
**Category:** UX / Reliability

#### Reproduction

```bash
# After search results load, scroll makes element visible but click still fails
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- click e4564 --follow
```

#### Expected Behavior

Element scrolls into view and is clicked, or a clear error message suggests scrolling.

#### Actual Behavior

```
⚠️  Click on e4564 did not result in navigation — page URL is unchanged. 
The element may be off-screen; try scrolling it into view first or use --follow to detect new-tab navigation.
```
The message is somewhat helpful but the `--follow` flag was already used and did not help. The real issue is that the element ref was from a previous `snapshot -v 1` (viewport 1) but the interaction was attempted after returning to viewport 0.

#### Root Cause Analysis

The ref was valid in viewport 1 but the click was attempted when the browser viewport was at a different scroll position. The error message conflates two issues: (1) element being off-screen and (2) ref being from a different viewport context.

#### AI Suggested Improvement

- Automatically scroll the element into view before clicking when it's off-screen (like Playwright's `scrollIntoViewIfNeeded`)
- Improve error message to distinguish between "ref from different viewport" vs "element scrolled out of view"
- Consider warning users when they snapshot one viewport and try to interact with elements from another

### Issue 3: Snapshot output triggers unintended pager, disrupting automation flow

**Severity:** Medium
**Category:** CLI Experience / UX

#### Reproduction

```bash
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- snapshot -v 0
```

#### Actual Behavior

On large pages (49 KB, 416+ lines), the snapshot preview triggers the terminal pager with `--More--`, requiring manual key presses to continue. This breaks automation flow for AI agents.

The snapshot YAML output is piped through a pager for human readability but is too large for agent consumption. The SKILL.md warns about this ("Don't cat snapshot files — they can exceed 256KB") but the inline preview itself triggers pagination.

### Issue 5: `snapshot grep` escape behavior differs from standard grep — discoverability gap

**Severity:** Low
**Category:** Discoverability / Documentation

#### Reproduction

```bash
cargo run --manifest-path cli/browser4-cli/Cargo.toml -- snapshot grep "龙虾\|武汉"
```

#### Expected Behavior

Pattern matches either "龙虾" or "武汉" (standard grep alternation syntax).

#### Actual Behavior

```
Note: Converted grep-style alternation `\|` to `|` in pattern. Rust regex uses bare `|` for alternation (like ERE/egrep). Use `snapshot grep -F` for literal matching.
```
The pattern works but the note reveals a discrepancy between the documented/POSIX grep syntax and the actual Rust regex engine.

#### Root Cause Analysis

The command is named `grep` suggesting POSIX BRE syntax, but the underlying engine uses Rust regex (ERE-like) syntax. The auto-conversion is helpful but the mismatch could confuse users coming from standard `grep`.

#### AI Suggested Improvement

- Document the regex flavor in `--help` output (e.g., "Patterns use Rust regex syntax; use `|` not `\|` for alternation")
- Add this to the warning/note in SKILL.md section on `snapshot grep`
- Consider accepting both `\|` and `|` silently without the note (since the conversion already works)

### Issue 7: Baidu search results open links in new tabs — agent must track tab sprawl

**Severity:** Low
**Category:** Task Execution / UX

#### Reproduction

Click any organic search result link on Baidu. With `--follow`, the CLI detects and switches to the new tab, but the original search results tab remains open. After reading the article, the user must manually `tab-list` and `tab-select` back to the search results.

#### Expected Behavior

Perhaps a `--back` or `--close-tab-and-return` option that closes the current tab and returns to the previous one after reading.

#### Actual Behavior

Tabs accumulate (3 tabs after clicking 1 link). Each return to search results requires 2 commands (`tab-list` + `tab-select N`).

#### Root Cause Analysis

Baidu uses `target="_blank"` links. The `--follow` flag handles this correctly but there's no convenience command for "go back to the tab I came from."

#### AI Suggested Improvement

- Add a `tab-back` or `tab-previous` command that switches to the previously active tab
- Consider a `click --back` option that clicks a link, waits for load, and provides a simple way to return
- Add tab count to `tab-list` output or warn when tab count exceeds a threshold
