### Issue 1: PowerShell -v/-i flags silently consumed by b4w.ps1 parameter binder

**Severity:** Critical
**Category:** Reliability

#### Reproduction

./b4w.ps1 -- snapshot -v 0 --stdout
./b4w.ps1 snapshot -v 0 --stdout
./b4w.ps1 "snapshot" "-v" "0" "--stdout"

#### Expected Behavior

The snapshot command should execute with -v 0 flag, showing viewport 0 of the accessibility tree.

#### Actual Behavior

The -v flag is consumed by PowerShell's parameter binder (matching -Verbose). The CLI receives 'snapshot 0' or 'snapshot-0' as the command, producing 'Unknown command: snapshot-0' or help text. Even quoting each argument individually does not prevent the issue when running via bash → pwsh -File.

#### Root Cause Analysis

When bash invokes ./b4w.ps1 (shebang: #!/usr/bin/env pwsh), pwsh receives arguments via -File mode. Despite b4w.ps1's param() block using ValueFromRemainingArguments, pwsh's own parameter binder processes -v and -i before the script's param() runs. The b4w.ps1 script's $SafeArgs quoting (lines 442-447) runs inside the script, which is too late — the flags are already consumed. The SKILL.md documents this but the workaround (-- separator) fails with pwsh -File. The b4w.sh wrapper solves this by using -Command mode with individually-quoted args.

#### Code Pointer

`b4w.ps1: line 16-19 (param block), lines 442-460 (SafeArgs construction). The fix likely requires changes to how the script receives or forwards arguments, potentially using --% (stop-parsing) or $args instead of param().`

#### AI Suggested Improvement

- Document that b4w.ps1 should ONLY be used from within a pwsh terminal, not from bash
- Update b4w.ps1 to detect when -v/-i are being consumed and emit a clear error: 'Flag -v was intercepted by PowerShell. Use b4w.sh from bash, or run snapshot -v 0 from within pwsh.'
- Consider rewriting b4w.ps1 param() to not use ValueFromRemainingArguments and instead use $args directly
- Make the -- passthrough work reliably from bash: the script should strip -- but preserve all subsequent args as literals
