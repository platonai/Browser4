## Summary

The browser4-cli `loop` command is well-designed: pause/resume/stop lifecycle is clean, state persistence works reliably, timeout enforcement is accurate, and the named-loop system supports concurrent loops. The core mechanisms (shell mode, subcommand mode with `b4w.sh`) work as documented.

The primary pain points are **(a)** the `b4w.ps1` wrapper's inability to handle `--` for subcommand mode (a documented feature broken in the primary wrapper), and **(b)** unreliable plain-text mode execution due to server-side timeouts. These two issues affect first-time user experience significantly — one of three loop modes is broken in the default wrapper, and another is unreliable at runtime.

The loop framework itself earns a rating of **8/10** for its design. The wrapper and documentation issues bring the overall first-time user experience down to **6/10**.
