### Issue 2: Backend times out after `htmlsnapshot summary` on large pages, requiring session restart

**Severity:** High

**Category:** Reliability

**Reproduction:**
```bash
goto "https://baike.baidu.com/item/华为技术有限公司/6455903"
htmlsnapshot                          # Works (returns metadata)
htmlsnapshot summary                  # Times out after 60s
```
After the summary timeout, ALL subsequent commands (eval, htmlsnapshot get, goto) fail with "Ping timeout" or "HTTP request timed out".

**Expected:** A single command that times out should not corrupt subsequent operations. The backend should recover gracefully.

**Actual:** `htmlsnapshot summary` on a 3.3MB page caused a persistent backend hang. Only closing and reopening the session (`close` → `goto`) restored functionality. The `status` command reported "Server health: UP" even while operations were failing.

**Root Cause:** The summary generator may be holding a lock or blocking a thread that subsequent operations also depend on. The timeout is detected by the CLI HTTP layer, but the backend operation continues running and blocks the browser session.

**Code Pointer:** Backend `html_snapshot_summary` MCP tool implementation; session-level resource locking.

**AI Suggested Improvement:**
- Add a hard timeout on backend summary generation that kills the operation and releases resources
- Isolate summary computation from the browser interaction thread
- Return partial results if summary exceeds a time budget
- Have `status` report whether the browser session is actually responsive, not just the HTTP listener

### Issue 3: `eval` and `htmlsnapshot get` fail with generic "Ping timeout" — no diagnostic info

**Severity:** Medium

**Category:** Reliability / UX

**Reproduction:**
```bash
eval "document.title" --json
# → ERROR: browser_evaluate failed: Ping timeout
htmlsnapshot get all text ".basicInfo-item.name" --all
# → HTTP request timed out [timeout=30s]
```

**Expected:** Error messages should indicate whether the timeout is due to (a) backend overload, (b) page JavaScript not loaded, (c) selector evaluation taking too long, or (d) session hung.

**Actual:** Both produce "timeout" messages with no diagnostic information. The user can't tell if the problem is the command, the selector, the page, or the session state.

**Root Cause:** Timeout errors from the backend are passed through without classification. The CLI layer doesn't distinguish between different timeout causes (page load, JS execution, selector matching, backend hung).

**Code Pointer:** CLI error formatting layer; backend MCP tool timeout handling.

**AI Suggested Improvement:**
- Classify timeout errors by phase: "page not ready", "JS execution timeout", "backend unresponsive", "session hung"
- After a timeout, automatically run a lightweight health check and report whether the session is still usable
- Add a `--timeout` flag to allow users to extend timeouts for large pages

### Issue 5: `htmlsnapshot summary` is not resilient to large pages (3.3MB HTML)

**Severity:** Medium

**Category:** Reliability

**Reproduction:**
```bash
goto "https://baike.baidu.com/item/华为技术有限公司/6455903"
htmlsnapshot               # Reports 3348 KB
htmlsnapshot summary        # Times out after 60s
```

**Expected:** The summary command, which is designed to compress pages to <1% of original size, should handle a 3.3MB page within a reasonable time budget. Or it should report that the page is too large and suggest alternatives.

**Actual:** The command hangs for 60 seconds then times out, and the timeout corrupts the session state (see Issue 2).

**Root Cause:** The summary algorithm may have exponential complexity on certain page structures, or it may be trying to process every DOM node in a deeply nested tree.

**Code Pointer:** Backend `html_snapshot_summary` MCP tool; WPSI generation algorithm.

**AI Suggested Improvement:**
- Add a node budget (e.g., cap at 50K DOM nodes) with graceful degradation
- Implement progressive summary generation with a time budget
- Return an error immediately for pages exceeding a configurable size threshold
- Document the expected page size limits for each command


**Expected:** Either the quoting works, or the error message clearly indicates the expression was malformed due to shell escaping.

**Actual:** Shell quoting silently corrupts the JS expression, and the resulting error ("Ping timeout") is misleading. The documented workaround (`--file`) works but adds friction — requires writing to a temp file for every query.

**Weaknesses:**
