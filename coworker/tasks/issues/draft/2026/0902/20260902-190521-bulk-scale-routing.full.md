## Section B — Execution Trace

1. **Setup.** Verified repo root/branch; `./b4w.ps1 help`; read SKILL.md fully (§4b lines 317–330, §4e lines 388–446) + the four reference pages. Scratch files confined to `.test-sessions/`.
2. **AC1 pass.** Query returned 6 correlated rows. Discovered default output is a raw JSON envelope; `--format table` exists only in `--help` (issue #3). Noted: raw HTML uses `<article class="product-card">` while the snapshot DOM is driver-normalized to `div.product-card` (injected `vi=`/`normalizedURI` attrs) — documented selectors match the snapshot DOM, not View-Source.
3. **AC2 pass.** 3 correctly attributed rows.
4. **AC3 blocked in Git Bash.** `crawl … -olp "/product/"` → `Crawl completed. 1 pages found.`, **exit 0, no diagnostic** — the CLI prints its backend diagnostic only at `page_count == 0` (main.rs:11359), unreachable because the seed is counted (issue #4; crawl.md:358's "Completes with 0 pages" never happens). Misdiagnosed initially as a backend pattern-matching bug; a full backend rebuild was triggered during the hunt.
5. **Environment detour: stale backend (issue #5).** Auto-started backend was 4.13.11-SNAPSHOT (jars ~7 days older than 4.13.13-SNAPSHOT sources) — the daemon's `existing_runtime_bundle` fast path (daemon.rs ~4240–4330) never checks staleness. Fixed via `mvn install -P"all-main-modules,asset-bundle"` + `build-runtime-bundle.ps1`; the first bundle rebuild failed (jlink "directory already exists", broken `jvm.cfg` — issue #7); clean rebuild after `rm -rf _work` succeeded.
6. **AC1 transient 0-row episode (issue #6).** On the fresh backend the identical AC1 query returned `No data. 0 rows returned.` twice (exit 0) while curl showed HTTP 200 + expected markup; AC2/AC4 still worked, isolating the failure to the htmlsnapshot-query path in a no-prior-navigation session. Capture+export proved the engine's DOM held the 6 cards; after a `goto`+`htmlsnapshot` warm-up, the exact query returned 6 rows repeatedly (bare `query <url>` included). Not reproducible after warm-up; contradicts the documented "query reuses cache" model. Also confirmed parse errors (e.g. unknown `DOM_COUNT`) surface in the envelope with **exit 0** (→ issue #3).
7. **AC3 root cause: MSYS.** The rebuilt backend's diagnostics exposed the effective pattern as `'C:/Program Files/Git/product/'` — MSYS2 path conversion of the leading-slash value when bash spawns pwsh. A/B proof: identical command inside PowerShell found the products. `b4w.sh` (the documented Git Bash wrapper) and `b4w.ps1` have no `MSYS2_ARG_CONV_EXCL`/`MSYS_NO_PATHCONV` guard and docs don't warn (issue #1).
8. **AC3 canonical depth-2 run + new regression (issue #2).** From PowerShell: discovery and category exclusion correct, but the crawl listing showed per-round title collapse and duplicate URL entries, with nondeterministic page totals (7–8 vs 10 on the old backend, which listed distinct correct titles). X-SQL row extraction stayed correct. Progress line re-prints "waiting for first page…" mid-run and all listed pages are labeled `depth=1` (issue #9). Pointers: `CrawlService.kt` `crawlDepth1` (~668) / `crawlDepthN` (~749).
9. **AC4/AC5/AC6 passes** (details above). Extra findings: `swarm close` claimed "3 locally tracked pending task(s) marked as failed (closed)" for completed tasks (issue #8); `swarm create` warned about stale tasks from unrelated prior sessions (issue #10).
10. **Cleanup.** Closed eval-created sessions (`price-watch`, default); `wechat-edge` (other user, created 09-01) left untouched.
